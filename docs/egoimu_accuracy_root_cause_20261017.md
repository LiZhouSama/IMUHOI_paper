# EgoIMU 与当前 IMUHOI 的精度差异：受控诊断

对象是当前 `vc-imuhoi + ot-imuhoi` 基线，不用IMUHOI++的分数代替原版复现。
本轮没有修改两套生产源码、预处理数据或checkpoint，没有启动新的训练。
全部交叉推理均覆盖相同1177条OMOMO测试序列。

## 结论及证据边界

当前Obj精度下降的直接环节，已定位到**当前VC学到的物体速度误差更有持续偏差和时间相关性**，
以及当前OT对这组速度输出的纠偏能力较弱。它不是VC网络前向搬错，也不是物体IMU或速度GT改变。

产生这些权重行为的训练过程明显没有对齐：窗口、实际训练序列、更新次数、损失权重、学习率、
选checkpoint标准、窗口边界特征和数值训练方式均不同。下文区分固定权重干预已证实的性能来源，
与仍需单因素重训才能分配贡献的训练因素；不能把某一个超参数宣布为唯一原因。

原版保存权重原生评估已复现论文表2：Obj11.305567、HOI17.443645、MPJPE2.349545、
root11.070070cm，Jitter2.768413mm/frame²，五项保留两位小数均一致。
当前基线offline final为16.012460、19.705657、2.352126、9.086146cm。

## 1. 先排除前向实现和物体输入错误

在原版eval中缓存原始模型输入、HP/VC/OT中间预测以及原生评估使用的GT/预测SMPL-H关节；
导出时重测四项主指标与已复现结果一致。随后在独立进程加载当前VC/OT实现，避免两仓库同名模块污染。

对全部1177条序列：

| 对照 | 最大绝对差 |
|---|---:|
| 相同原版权重、相同输入，原版VC vs 当前VC：物体速度 | 0 |
| 同上：手速度 | 0 |
| 同上：接触概率 | 0 |
| 原始预处理 vs 当前预处理：完整序列物体IMU | 0 |
| 同上：初始物体速度 | 0 |
| 同上：物体速度GT | 0 |

同一VC权重在两份数据上产生的物体速度也逐元素相同。物体速度分支推理只依赖物体IMU与初始物体速度。
人体IMU发生变化，但不会在推理时直接进入该独立物体速度网络。
人体输入、接触标签仍可通过训练时接触损失的梯度间接影响物体速度网络，不能因此排除所有预处理的训练影响。

当前OT加载原版权重并喂原版HP/VC中间量后，平均Obj11.305578cm，几乎等于原生11.305567cm；
平均HOI17.442545cm，相比原生17.443645cm仅差约0.0011cm。
逐帧最大位置差约1.213mm；先验的`log(prior+eps)`与`log(clamp(prior))`等数值处理不同，
不支持把前向本体差异解释为约4.7cm的平均Obj退化。

实现：`model/rnn/velocity_contact_IMUHOI.py`、`model/rnn/object_trans_IMUHOI.py`。

## 2. 固定原版HP、数据与GT，交叉更换训练权重

以下均运行当前VC/OT实现，只更换权重；HP预测、物体输入、初始状态和原版指标GT固定。
这是条件干预诊断，不是四个分别重新训练的端到端系统。

| VC权重 | OT权重 | Obj cm | HOI cm |
|---|---|---:|---:|
| 原版 | 原版 | 11.30558 | 17.44254 |
| 当前 | 原版 | 14.66884 | 18.73953 |
| 原版 | 当前 | 11.42832 | 17.58085 |
| 当前 | 当前 | 16.01957 | 20.54514 |

当前VC/OT权重在原版HP与数据上仍得到Obj16.01957cm，几乎重现当前完整基线的16.01246cm。
因此，仅将HP、测试输入和评估GT换回原版不能消除Obj差距。
更换VC已引起大部分退化；OT单独更换影响较小，但与当前VC存在额外失配，不能把两个模块的影响简单相加。

进一步把VC输出中的接触概率和物体速度分开交换：

| 固定原版HP与原版OT | Obj cm |
|---|---:|
| 原接触 + 原速度 | 11.30558 |
| 当前接触 + 原速度 | 10.81774 |
| 原接触 + 当前速度 | 15.48825 |
| 当前接触 + 当前速度 | 14.66884 |

只换当前速度便增加约4.18cm；只换当前接触在该条件下反而改善约0.49cm。
所以这轮Obj损失主要由物体速度输出触发，不应笼统归因为接触分类变差。
这不是对所有动作或所有接触指标的普遍结论。

## 3. 速度RMSE更低，为什么轨迹反而更差

均先在序列内统计，再对1177条序列等权平均：

| 物体速度/积分诊断 | 原版权重 | 当前VC best权重 |
|---|---:|---:|
| 速度RMSE m/s | 0.08655 | **0.06501** |
| 序列平均误差向量的模 m/s | **0.03512** | 0.05396 |
| 约1秒低通后的误差模 m/s | **0.04407** | 0.07710 |
| 去均值后相邻帧误差相关性 | **0.6310** | 0.9270 |
| 独立速度积分Obj cm | **11.52364** | 15.85164 |
| 序列末帧Obj cm | **19.93866** | 32.18300 |

位置误差累积的是有方向的速度误差：

$$\Delta p_T = \Delta t\sum_{t<T} e_t.$$

逐帧MSE只描述单帧误差能量。累计位置误差还取决于不同时间误差的相关性：

$$\mathbb{E}\|\Delta p_T\|^2=\Delta t^2\left(\sum_t\mathbb{E}\|e_t\|^2+2\sum_{s<t}\mathbb{E}[e_s^\top e_t]\right).$$

当前误差更小但更持续，不能像高频正负误差那样互相抵消。
时间分组中，当前VC在前约30%的帧优于原版，之后逐渐变差；这与短窗口目标无法保证长时积分精度相符，
但不能单凭这一曲线认定“窗口长度就是唯一训练原因”。

事后用测试GT扣除每条序列的平均速度偏差，原/当前积分误差变为4.93/7.42cm，
支持均值偏差和剩余低频误差的影响。**这是GT oracle诊断，不是可部署方法，也不能作为正式成绩。**

## 4. 实际训练不是同一配方

原版参照应是生成论文权重的 `EgoIMU/outputs/IMUHOI/omomo/training_config.yaml`，
不能把后来改过的 `EgoIMU/configs/IMUHOI_train.yaml` 默认值当作该run实际训练参数。

| 项目 | 原版已保存run | 当前基线实际值 |
|---|---|---|
| VC obj_vel/hand_vel权重 | 10/10 | 1/1 |
| VC接触权重 | 1 | 1 |
| OT物体位置/速度一致性权重 | 1/1 | 0.1/0.1 |
| 训练窗口 | 120帧 | 60帧 |
| 实际可训练序列 | 4115 | 4701 |
| VC batch | 100 | 800 |
| 每epoch抽样 | 每序列1次，无放回shuffle | 有放回抽样，期望每序列4次 |
| VC每epoch更新 | 41 | 23 |
| VC LR衰减 | 全部参数50/150 | 速度100；接触30/50/70 |
| HP/OT每epoch更新 | 68 | 23 |
| 联合每epoch更新 | 82 | 23 |
| 联合初始LR | 0.002 | 0.0002 |
| 联合最大epoch | 300 | 100，实际epoch36早停 |
| 前向数值 | FP32（GradScaler本身不等于autocast） | BF16 autocast，LSTM核心回退FP32 |
| 梯度裁剪 | 原训练器未执行 | 全局范数1.0 |

4115/4701不是文件划分恢复失败：文件成员已一致为4705/1177；原loader还要求长度≥121和obj_contact≥10帧，
当前60帧只需长度≥61且接触门槛为0。恢复文件名单并没有恢复训练时真正使用的样本集合。

更新次数直接从checkpoint的optimizer state读取，不是从epoch数猜测：

| 选中权重 | 实际optimizer step | 保存时LR |
|---|---:|---|
| 原版VC best，epoch270 | 11111 | 0.00008 |
| 当前VC best，epoch110 | 2553 | 接触0.000016，速度0.0004 |
| 当前VC final，epoch299 | 6900 | 同上 |
| 原版联合best，global epoch1040 | 11562 | 0.00008 |
| 当前联合best，epoch6 | 161 | 0.0002 |
| 原版联合末轮，global epoch1199 | 24600 | 0.000000128 |
| 当前联合final，epoch36 | 851 | 0.0000016 |

更大的batch和4倍窗口抽样意味着不能把更新少简单等同于“看过更少帧”；
但梯度噪声、更新次数与LR阶段确实都不等价。训练种子10一致不能消除这些差异。

### 窗口边界输入也不同

原loader先裁剪再生成速度和IMU；当前预处理保存整段特征，训练时直接切片。
完整序列物体输入完全相同，不代表训练窗口输入相同。
在测试轨迹的中间窗口做特征探针，内部加速度逐元素一致，差别集中在边界：

| 同长度窗口，重算 vs 整段特征切片 | 60帧 | 120帧 |
|---|---:|---:|
| 探针序列数 | 1175 | 1014 |
| 边界8帧加速度平均绝对差 m/s² | 0.47638 | 0.37164 |
| 初始速度差的平均模 m/s | 0.03307 | 0.02987 |
| 内部加速度最大差 | 0 | 0 |

窗口起点的前向差分与整段中心差分、加速度补零/平滑边界均改变了RNN的训练初始化分布。
该探针量化的是输入分布变化，不是训练消融所得的精度收益。
对应 `EgoIMU/dataloader/dataloader_IMUHOI.py:350`、`dataset/dataset_IMUHOI.py:655`、`process/preprocess.py:335`。

### checkpoint标准也有变化

- 原版HP验证按`10*pose_reduced + root_trans`选择；当前`HumanPoseLoss.compute_test_loss`对原始损失直接求和，
  实际为`pose_reduced + root_trans`。联合阶段的HP辅助验证又使用加权值。
- 原版联合验证包含HP的pose/root和OT的方向、长度、左右HOI；当前联合选点只使用OT加权的
  `hoi_error_l + hoi_error_r + obj_trans`。
- 当前采用固定验证窗口，原版窗口起点随机；两者内部验证虽都加std0.1噪声，也不能成为同一个选点过程。

当前VC final的独立积分Obj为15.14890cm，比其best的15.85164cm低约0.70cm，
但仍明显高于原版11.52364cm。选点不匹配确实有影响，却不是全部差距；不能事后按测试集挑选替换正式基线。
代码：`train/rnn/loss/human_pose_loss.py:194`、`train/rnn/train_object_trans.py:225`。

## 5. 已确认的接口与HP语义差异

### OT训练接口确有问题

当前 `train/rnn/train_object_trans.py:760` 用掌根作为IMUHOI OT的训练和内部验证输入；
`train/rnn/loss/imuhoi_loss.py:250` 用手腕做几何监督；
`model/rnn/imuhoi_model.py:360` 在独立评估时选择手腕。
原版输入/监督均为手腕。这个训练契约必须先统一，再声称是等价原版基线。

固定现有权重只把推理锚点换成训练掌根，Obj仅改善0.00347cm。
它不是当前4.7cm差距的直接数值解释，但训练中输入/目标矛盾仍可能削弱几何头；这必须通过重训验证。
当前OT门控初始化还把GT初始物体速度换成VC首帧预测；先前完整测试的固定权重敏感性小于0.001cm。

### HP不是原公式的逐项搬运

同一原版head输出与FK关节下，原版根融合公式化简为：

`v = (1-w)*3*(R*v_local) + w*(foot_displacement + gravity)`。

当前为：

`v = (1-w)*(R*v_local) + w*(30*foot_displacement + gravity)`。

另外，原版floor算子在速度累加量上修正，当前在加入初始位置后的米制轨迹上修正；
当前积分忽略首帧增量、floor阈值0.03，原版包含首帧增量、阈值0。
当前还启用half-width=7平滑（在forward内部确实生效）并新增脚接触BCE监督。

复算原版根轨迹与缓存输出最大差小于7.2e-7m，确认上述旧公式匹配实际执行。
给同一组原版head/旧FK套当前根运动算子，root误差变为46.82cm，原版为11.07cm。
**46.82不是当前重训HP的成绩**：当前HP在自身数据上实际root约9.09cm。
该反事实仅证明旧权重的标定语义与新公式不兼容，不能据此判断物理修正应全部撤回。
代码：`EgoIMU/models/IMUHOI_stage_net.py:532`、`model/rnn/human_pose.py:391`、`:543`、`:635`。

### 评估人体GT也变了

原版eval用SMPL-H male重新生成GT/预测关节；当前使用SMPL-X neutral/zero-betas canonical GT，
HOI公式虽然已统一，骨架、接触帧集合仍不同。此前全量审计的根相对关节均差4.2564cm，
同手腕手物向量均差14.3919cm，左/右手接触约9.12%/9.67%帧不一致。
它们影响HP与HOI的可比性；但本轮已证明即使固定原版HP和GT，Obj差距仍基本存在，不能把它们作为主要Obj归因。

## 6. 修正之前关于门控的判断

原版OT在这1177条序列上的IMU平均权重也达到99.9201%；当前完整基线为99.9819%。
因此“IMU权重非常高”不是独属于失败基线的特征，不能单凭这一现象认定门控塌缩是主因。
更有效的证据是换速度/接触的干预结果、累计速度偏差，以及OT对当前VC的额外失配。
该结论替代此前仅依据当前门控统计作出的较强归因。

## 建议的最短修复/验证路径

1. 先统一IMUHOI OT训练、内部验证、独立推理和几何监督的手腕契约，明确六维门控初始化；
   保留现有实验，不覆盖旧权重或成绩。
2. 优先只重训VC，不必重新从HP开始。用同一训练成员、同一初始权重和随机采样轨迹，
   对照120/60帧、窗口内重算/缓存切片、原版/当前损失和LR配方；评价同时记录速度RMSE、偏差、积分漂移。
   将长序列漂移放入独立验证集，不能继续只用短窗口MSE/BCE代理选点。
3. VC的积分水平恢复后再重训OT及联合阶段，匹配实际更新预算和选点标准。
4. 若目标是严格复现论文数值，应单独做paper兼容路径：原数据/SMPL-H与原HP运动语义、FP32、原配方。
   若目标是在新canonical数据上提高精度，则保留新物理和骨架改进，用控制变量实验证实收益，
   不必全局退回旧公式。

本轮已经找到直接的性能损失来源，但尚未对所有训练差异逐项重训，所以不声称“把某个权重改10倍就必然恢复论文”。
