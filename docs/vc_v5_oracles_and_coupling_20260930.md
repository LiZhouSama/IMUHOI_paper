# VC 能为 OT 买到多少：闭环 oracle、误差结构与 VC-v5（2026-09-30）

## 结论先行

用户的出发点：`docs/vc_ot_cross_ablation.md` 中 VC-v4（人体姿态先验提供交互起止先验）相对 IMUHOI VC 的收益不明显；希望继承 v3/v4 的思路，用新方法改进 VC 测试结果或 OT 精度。

第一性原理地看，VC 对 v2 OT 只输出两类东西：**接触概率**（直接决定四路固定融合权重 `build_contact_fusion_weights`，也是预测器输入）和**物体速度**（IMU 积分候选的位移，也是预测器输入）。所以先回答"完美的 VC 值多少"，再决定改哪里。

1. **天花板（闭环 oracle，§1）**：OMOMO 上接触几乎没有空间（GT 接触 −0.29 obj / −0.34 HOI）；BEHAVE 上手接触是 HOI 杠杆（GT 手接触 HOI −1.97）。**物体速度在两个数据集都是 obj 杠杆**（GT 速度 OMOMO −0.86、BEHAVE −0.77）。
2. **误差结构（§2–3）**：BEHAVE 的手接触错误不是起止时刻问题——70% 的错帧离 GT 转折 >15 帧，是长时间持续误判；v4 的姿态先验在 BEHAVE 上主要在记忆（训练 F1 0.91 vs 测试 0.80）。BEHAVE 长序列上 VC 速度误差 ≈ 在线速度初值误差（0.23–0.35 m/s，与物体真实速度同量级）：网络只在 GT 初值上训练过，在线时"盲信"错误初值。
3. **方法（§4）**：VC-v5 保留 v4 的姿态先验分支（回答"交互何时可能开始/结束"），为接触网络补上旋转不变的物理耦合证据（回答"此刻手是否在带着物体动"）；v5ar 再加**窗口初值鲁棒训练**（训练时扰动速度初值，对齐在线协议的曝光偏差）。
4. **结果（§5，同一编排命令、只换 VC，seed 42）**：

7. **初值问题（§9，10-02 补充）**：v5ar 把速度初值误差传到输出的比例从约 0.6 降到约 0.2，速度初值协议（自身输出 vs 轨迹差分）在两个数据集上都不再影响结果（≤ 0.04 cm），而 v4 在 BEHAVE 上改回自身输出会 obj +1.73，所以可以统一协议（OMOMO 上两种协议对 v4/v5ar 都只差 ≤ 0.04，最省事的是都用差分初值）；初值本身的误差（在线没有准确的速度参考）没有变；剩余的速度上限（闭环 GT 速度）BEHAVE obj −0.14（v4 −0.77）、OMOMO −0.45（v4 −0.86）。扣除第 0 帧伪影后，窗口接触初值的误差链在 v4 上就不显著、在 v5ar 上约为 0；第 0 帧伪影仍在（v5ar −0.16 / −0.15）。v5b 只有插入评测（与 v5a 打平），没有完整管线。
8. **10-02 之后（§10–§11）**：统一在线协议（差分速度初值 + HP 平滑，所有数据集）已写入基础配置，OMOMO 重训后基本无代价；初始接触状态取 0.5 显著更差，建议三个通道都取 0（完全不用 GT，代价 ≤ 0.04）；"动但无手"帧的误差是继承来的，速度修不了，带 HP 根误差的完美锚上限只有 −0.9，静止物体当路标校正根位置不成立；v5ar 上手接触仍值 BEHAVE obj −1.18 / HOI −1.54，约一半测试错误来自泛化差距；v5br（朝向归一化）两种子与 v5ar 无差别。

## 2. VC 误差结构（在线 dump，`v2_armrot_biclose_vlock_20260930/dump_*_base.pt`）

| | OMOMO | BEHAVE |
|---|---|---|
| 手接触 pooled F1 | 0.951 / 0.952 | 0.859 / 0.865 |
| 错帧中离 GT 转折 ≤15 帧的比例 | 60% | 30% |
| 起/止时刻 MAE（匹配段） | ~4 帧 | 16 / 24 帧（含长错段） |
| 在线发布接触段数 / GT 段数 | 1.3× | 4.2×（810 vs 192） |
| 全部通道正确帧的 obj | 13.70（整体 13.94） | 22.18（整体 24.46） |

- BEHAVE 错误类型分散：漏检 8.5% 帧、误报 4.8%、双手↔单手 6.9%、左右互换 0.6%。最差物体是被推/拖/滚的大物体（boxlarge、chairwood、tablesmall、yogaball，漏检 17–19%）；小物体 F1 >0.92。误报率随帧号单调上升（60–240 帧 0.042 → 1200+ 帧 0.075）。
- 在线闪烁可被 HMM 固定滞后平滑压到 ~280 段，但 F1 仅 +0.008 → 平滑不是解法。
- 同一 VC 整段离线单次前向 F1 反而更低（0.807 vs 在线 0.859）：滑窗重初始化本身在帮忙。
- 窗口接触初值（v4，BEHAVE final）：warmup 之后每个窗口都给 GT 初值 → 23.72 / 17.25；初值设为中性 0.5 → 25.43 / 18.61，初值携带大量信息。GT 初值与第 1 帧初始状态同时开启为 23.72 / 17.23，比单独修正第 0 帧伪影（§5.4，23.77 / 17.46）只多 −0.05 / −0.23（不显著）：已发布初值的误差链是次要因素，接触初值翻转训练不值得做。（初版把 GT 初值的收益直接归给第 0 帧修正，推理有误，见 §9.3。）
- "物体在动但手未接触"占 BEHAVE 7% 帧、物体误差 40.9 cm；但 GT 上 |v_obj − v_root| = 0.35 m/s 大于 |v_obj| = 0.23 m/s，按根位移跟随不成立；按躯干锁存偏移的候选只有在 GT 接触下才有 −0.87，用 VC 接触时 ±0.1，且在 OMOMO 上 +0.94（那里是真正的推/滑）→ 放弃。

## 3. 速度：在线初值是主要误差源

- BEHAVE 在线协议的速度初值 = 已发布物体轨迹 3 帧差分（t−60 处）。其误差 60–239 帧 0.23 m/s、240–599 帧 0.30、600+ 帧 0.35，与真实速度（0.31–0.35）同量级；VC 发布速度误差 0.23 / 0.28 / 0.30 ≈ 初值误差。
- 在 GT 初值下，LSTM 在窗口末端的误差 0.096 m/s（显式积分 0.115）；初值加 N(0, 0.15²) 后 LSTM 只把 0.235 纠正到 0.206：网络训练时从未见过错误初值，因此"盲信"初值。
- 在线没有好的速度参考（窗口初始帧处的误差，m/s）：

| 初值来源 | BEHAVE（\|v\| 0.350） | OMOMO（\|v\| 0.556） |
|---|---:|---:|
| VC 自身上一窗口输出（OMOMO 现协议） | 0.279* | **0.139** |
| 已发布轨迹 3 帧差分（BEHAVE 现协议） | 0.342 | 0.362 |
| 已发布轨迹 10 帧差分 | 0.325 | 0.372 |

  *该值是在差分初值协议下测得的 VC 输出；若改用自身输出作初值，误差会跨窗口随机游走（09-22 的原问题）。BEHAVE 上差分初值几乎等于"给 0"；OMOMO 上差分初值更差，但端到端只差 +0.04（§9.1）。
- 后处理不是解法：速度收缩/按移动概率门控在开环回放里最多 −0.09（BEHAVE），OMOMO 上明显变差；跨窗口持续积分的互补速度滤波（手持拉向掌速度、静止拉向 0）把逐帧速度误差降到 0.20–0.22，但开环回放的物体误差反而变差（24.08 → 24.7）——决定漂移的是 IMU 主导段内误差的偏置而非逐帧大小。

## 4. VC-v5 设计（`model/rnn/velocity_contact_v5.py`，测试 `test/test_rnn_vc_v5.py`）

v5 = v4（朝向归一化 + 分模态归一化的双向姿态先验编码器、端点热图与预期头、条件接触分解，全部保留）+ 下列**旋转不变**证据：

- 每只手：`B = R_obj^T R_forearm` 的转速（刚性抓握时两者一起转，B 近似不变）、前臂转速、`|a_forearm − a_obj|`；
- 共享：物体转速、`|a_obj|`、掌间距及其变化率、两掌相对速度、两前臂相对转速；
- 每个信号取 `[t−5, t+5]` 与 `[t−20, t+10]` 的居中平均（不超过在线 10 帧前瞻）及其 log1p。手接触网络读全部（+48 维），物体移动网络读物体项（+8 维）。

动机：GBDT 探针（BEHAVE 测试集按序列分组 5 折）只用这些特征逐序列 F1 0.803 > VC-v4 0.784，叠加 VC-v4 概率后 0.842，说明物理耦合与姿态先验互补；它们都是标量不变量，无法记住序列的绝对朝向。

选项（默认关闭）：
- `v5_heading_normalize_imu`：把接触网络的 IMU/预测速度通道转到根 IMU 的朝向坐标系（v5b）。
- `v5_init_noise_prob`、`v5_obj_vel_init_noise_std`、`v5_hand_vel_init_noise_std`、`v5_contact_init_flip_prob`：仅训练时在部分窗口上扰动初值（v5ar 用 0.5 / 0.2 / 0.2 / 0；joint 阶段通过 `--set` 同样开启）。

训练协议与 v4 完全相同（`relabel_20260918_{ds}/vc_config.yaml`、同 HP、seed 42、全量 epoch 预算；`VelocityContactTrainer.train()` 没有早停，v4 当时也跑满；按分段测试集损失选 best.pt）。VC 分段测试集最佳总损失：BEHAVE v4 0.622 → v5a 0.562 → v5b 0.542 → v5ar 0.589（GT 初值下）；OMOMO 0.221 → 0.211 → — → 0.216。

### 5.4 评测协议中的第 0 帧接触标签伪影

`process/preprocess.py::compute_improved_contact_labels` 用后向差分计算手/物体速度（第 0 帧速度为 0），速度相似度项在第 0 帧恒为 0，**第 0 帧不可能被标成手接触**。全序列测试集的第 0 帧就是真实起点：BEHAVE/OMOMO 所有测试序列第 0 帧手接触都是 0，而第 1 帧分别有 31% / 41% 处于接触；分段训练集不受影响。在线评测以第 0 帧 GT 作为初始接触状态，于是 VC 的手接触 LSTM 从"无接触"起步：BEHAVE warmup 段（前 60 帧）手接触 F1 仅 0.66（独立 VC 0.48–0.50）。评测侧新增 `--contact_init_frame 1`；数据侧的根治是差分速度 `v[0] = v[1]`（需重建数据，未改）。

| BEHAVE final，v5a | 23.395 / 16.999 | 23.337 / 16.851（−0.06 / −0.15） |

### 9.1 两套速度初值协议从何而来

- 来源：09-22 用户提出的 BEHAVE 专用推理修正（`docs/long_horizon_hoi_diagnosis_20260909.md` §15）——`online_obj_vel_init_diff_frames: 3`，与 `human_pose_smoothing_half_width: 7` 同时引入，均默认关闭，只在 BEHAVE 运行上打开；OMOMO 一直沿用默认协议（VC 自身上一窗口输出）。所以两套协议是历史遗留，不是 v5 实验里的选择。
- 为什么只有 BEHAVE 需要：自身输出初值是一条跨窗口的链——发布帧 t 的窗口在 t−60 读 VC 自己的速度，而那个速度又以 t−120 的输出为初值……误差随"跳数"累积。两个测试集的长度差一个数量级：

| 测试集 | 序列数 | 长度中位 / 最长 | 平均每帧处在链的第几跳 |
|---|---:|---|---:|
| BEHAVE | 59 | 1424 / 3920 帧 | 12.6 |
| OMOMO | 1173 | 170 / 452 帧（88% ≤ 240 帧） | 1.1 |

  OMOMO 上链来不及累积，自身输出初值（60–240 帧 0.12 m/s）远好于轨迹差分（0.32 m/s：3 帧差分 = 位置差 × 10，发布位置 1 cm 的抖动就是约 0.14 m/s 的速度噪声）；BEHAVE 上链会漂（09-22 测得静止物体速度误差 2.5 → 22 cm/s，旧 p800 管线换差分初值 obj −9.4）。
- 在现管线上交换协议：

| | BEHAVE 差分（现协议） | BEHAVE 自身输出 | 配对 Δ obj / Δ HOI | OMOMO 自身输出（现协议） | OMOMO 差分 | 配对 Δ obj / Δ HOI |
|---|---|---|---|---|---|---|
| v4 | 24.084 / 17.854 | 25.813 / 18.421 | **+1.73 [+0.57, +3.13]** / **+0.57 [+0.15, +1.02]** | 13.366 / 10.443 | 13.405 / 10.466 | +0.04 [−0.01, +0.08] / +0.02 [−0.02, +0.06] |
| v5ar | 22.882 / 17.139 | 22.905 / 17.178 | +0.02 [−0.04, +0.10] / +0.04 [−0.01, +0.10] | 13.226 / 10.479 | 13.261 / 10.490 | +0.035 [+0.020, +0.054] / +0.011 [+0.002, +0.022] |

  OMOMO 上两种协议对 v4、v5ar 都无关紧要（≤ 0.04 cm，链只有约 1 跳；§3 按初值误差说"OMOMO 不应改成差分"高估了它的影响）。BEHAVE 上 v4 离不开差分协议（自身输出 obj +1.73），v5ar 不敏感。所以可以去掉这个按数据集选的开关：代价最小的统一方式是两个数据集都用差分初值——BEHAVE 现有结果不变，OMOMO 各行只差 ≤ 0.04 cm（需重评）；只比较 v5ar 系列时用哪个都行。HP 平滑是同日引入的另一个 BEHAVE 专用开关，统一协议时需在 OMOMO 上单独验证。在自身输出协议下，v5ar 相对 v4 的 BEHAVE 收益是 obj −2.91 / HOI −1.24。

### 9.2 v5 是否解决了在线速度初值问题

§3 的问题有两半：(a) 在线没有准确的速度参考，初值本身差；(b) VC 只在 GT 初值上训练过，把初值误差带到窗口末端（"盲信"）。

- v5a 没有动速度分支（耦合特征只进接触与物体移动网络），在线速度误差与 v4 相同（§5.1）。
- v5ar 的初值扰动训练针对 (b)。在线 dump（BEHAVE final，差分协议，`scripts/diag/vc_vel_init_chain.py`）：初值取发布帧 t 的窗口在 t−60 处实际读到的值；传递斜率 = 输出误差向量对初值误差向量的最小二乘斜率（1 = 原样传递，0 = 完全纠正）。

| 发布帧段 | 初值误差 v4 / v5ar (m/s) | VC 输出误差 v4 / v5ar | 传递斜率 v4 / v5ar | 相关系数 v4 / v5ar |
|---|---|---|---|---|
| 60–240 | 0.250 / 0.261 | 0.227 / **0.156** | 0.57 / **0.22** | 0.72 / 0.41 |
| 240–600 | 0.318 / 0.312 | 0.275 / **0.172** | 0.61 / **0.23** | 0.76 / 0.42 |
| 600+ | 0.362 / 0.342 | 0.303 / **0.178** | 0.55 / **0.20** | 0.73 / 0.40 |

  (a) 没有变化：差分初值误差仍与物体速度同量级（|v| ≈ 0.35）。(b) 大部分解决：初值误差只有约 1/5 传到输出，输出误差降 31–41%；OMOMO 自身输出协议下 240–600 帧段 0.316 → 0.115。§9.1 的协议不敏感就是 (b) 的直接后果。
- 没解决的部分：前 60 帧（warmup，GT 初值）速度误差略升（BEHAVE 0.074 → 0.096，OMOMO 0.075 → 0.086），因为 v5ar 对 GT 初值也打了折扣；剩余的速度上限（v5ar 管线上的闭环 GT 速度 oracle，`--oracle_vc_obj_vel`）：BEHAVE 上 GT 速度只再带来 obj −0.14 [−0.29, +0.01] / HOI −0.14 [−0.26, −0.04]（v4 管线上是 −0.77 [−1.31, −0.28] / −0.54 [−1.06, −0.10]），v5ar 的实际结果 22.88 已低于 v4 管线的 GT 速度上限 23.32——BEHAVE 上速度这根杠杆基本用完了。OMOMO 上 GT 速度仍带来 obj −0.45 [−0.58, −0.33]、HOI −0.03（v4 管线 −0.86 / −0.06）：速度空间还剩约一半，且只体现在 obj 上。

### 9.3 窗口接触初值（更正 §2 的推理）

§2 写"每个窗口都给 GT 初值 → 23.72 / 17.25，其中大部分来自第 0 帧修正"，推理有误：`--eval_vc_contact_init gt` 只替换 warmup 之后各窗口的初值，warmup 前向（第 0–59 帧）仍从第 0 帧的伪影标签起步，它与 `--contact_init_frame 1` 是互补关系，不是包含关系。补跑两者同时开启：

| BEHAVE final obj / HOI | 原协议 | 第 1 帧初始状态（cinit1） | GT 窗口初值（不含 warmup） | 两者都开 | 误差链 = 两者都开 − cinit1（配对） |
|---|---|---|---|---|---|
| v4 | 24.084 / 17.854 | 23.767 / 17.455 | 23.721 / 17.248 | 23.718 / 17.230 | −0.05 [−0.39, +0.28] / −0.23 [−0.58, +0.10]；F1 +0.019/+0.025（显著） |
| v5ar | 22.882 / 17.139 | 22.726 / 16.984 | 22.890 / 17.023 | 22.840 / 16.944 | +0.11 [−0.15, +0.44] / −0.04 [−0.18, +0.10]；F1 +0.008/+0.009 |

- 原结论不变，表述更正：第 0 帧伪影靠已发布状态向后传递，只要 warmup 之后每个窗口都拿到 GT 接触初值，伪影就只剩前 60 帧（v4 两列只差 0.003 / 0.018）；扣除伪影之后，"已发布接触作窗口初值"的误差链在 v4 上就不显著（HOI −0.23），在 v5ar 上约等于 0。
- v5 没有改窗口接触初值机制（`v5_contact_init_flip_prob = 0`），也没有修数据里的伪影；它只是对两者都更不敏感：伪影代价 v4 −0.32 [−0.80, +0.01] / −0.40 [−0.94, +0.06] → v5ar −0.16 [−0.43, +0.01] / −0.15 [−0.37, −0.01]；误差链 HOI −0.23 → −0.04。伪影的根治仍是数据侧 `v[0] = v[1]` 或评测侧 `--contact_init_frame 1`。

### 9.4 v5b
