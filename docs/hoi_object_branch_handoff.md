## 0. 一页速览

| 问题 | 答案 |
|---|---|
| 任务 | 6 个身体 IMU + 1 个物体 IMU → 全身 SMPL 姿态 + 物体 6-DoF 轨迹 |
| 物体位置怎么来的 | 接触时把"手→物体中心"当成一根虚拟骨骼，随物体旋转做 FK；不接触时保持静止 |
| 核心假设 | 一次抓握内，该骨骼在**物体坐标系**下方向和长度不变（刚性固连） |
| 假设的天花板 [oracle] | 单手段内 FK 误差 **6.41 cm**；整段序列 obj_err **5.03**、hoi_err **5.01** |
| 系统现状 [pipeline] | obj_err **13.92**、hoi_err **9.46**（新 v3），v2 基线 14.51 / 10.05 |
| 差距主因 | **不是假设不好，是手的位置不准**：换成真值手，误差立刻 13.02 → 5.03 |
| 最该努力的方向 | 用物体 IMU 反过来约束**人体手臂**（接触期间物体 IMU 就是手上的第 7 个传感器） |

一句话：**物体分支的建模已经接近它自身的天花板，剩下的误差 70% 以上来自人体姿态估计的手部漂移。**

## 1. 任务与数据

**输入**（30 FPS）：
- `human_imu` `[B,T,6,9]`：6 个身体 IMU，每个 9 维 = 3 维加速度 + 6D 旋转。
  传感器位置索引 `_SENSOR_POS_INDICES = [0,7,8,15,20,21]`（根、左右小腿、头、左右手腕位置），
  **旋转索引 `_SENSOR_ROT_INDICES = [0,4,5,15,18,19]`（根、左右大腿、头、左右前臂/肘）**。
  非根传感器存的是**根相对**朝向，需要 `R_root @ (R_root^T R_sensor)` 还原到世界系。
- `obj_imu` `[B,T,9]`：物体 IMU，同样是 3 维加速度 + 6D 旋转。
- 各类初值 `v_init / p_init / trans_init / obj_trans_init / contact_init / obj_vel_init`。

**输出**：24 关节 SMPL 姿态 + 根平移；物体平移 `pred_obj_trans`（旋转直接来自物体 IMU，不预测）。

**⚠️ 关键约束（很多改进想法死在这里）**：旋转传感器装在**肘部/前臂**，不在手上。
所以**手腕的转动完全不可观测**。这一条决定了后面一大半的设计空间。

**数据**：OMOMO，`process/IMUHOI++/processed_split_data_OMOMO_full/{train,test}`。
测试集 1173 个 `.pt` 文件；`eval_batch_online.py` 实际评测 **1015 条**（过滤掉长度不足窗口的）。
序列平均 177 帧（5.9 s），接触帧占 74%，其中 **54% 是双手同时接触**，平均每序列 1.69 个接触段、每段 85 帧。

**⚠️ 数据坑**：1173 个文件里有 **87 条（7.4%）物体在动但接触标签全为空**。
oracle FK 在这 87 条上误差 54.8 cm，把全集 oracle obj_err 从 5.86 抬到 9.49。
评测集（1015 条）已把它们全部排除，所以**评测数字不受影响**，但如果你重算 oracle 上界，
一定要说明用的是哪个集合，否则 9.49 和 5.03 会对不上。

## 2. 三阶段流水线

架构由 `cfg.model_arch` 选择（`"rnn"` 或 `"dit"`），本文档只讲 RNN 路径（`model/rnn/`），
它是物体分支实验的主线。三个模块串联，各自有独立 checkpoint，可以分别冻结/微调。

```
human_imu ──► HumanPose (HP) ──► 关节 + 手掌位置 h_L(t), h_R(t)
                   │
                   ├──────────────► VelocityContact (VC) ──► 接触概率 + 物体速度
human_imu,obj_imu ─┘                        │
                                            ▼
                            ObjectTrans (OT) ──► pred_obj_trans p(t)
```

### 2.1 HumanPose（`model/rnn/human_pose.py`）
从 6 个 IMU 回归全身姿态与根平移。输出里物体分支要用的是：
- `pred_palm_glb_pos` `[B,T,2,3]`：**左右手掌锚点**世界坐标（下一节详述这个点的定义）
- `pred_hand_glb_pos`：手腕位置
- `root_trans_pred`、`p_pred`（reduced 关节 6D）

### 2.2 VelocityContact（`model/rnn/velocity_contact.py`，当前用 `v4`）
输出：
- `pred_hand_contact_prob` `[B,T,3]` = (左手接触, 右手接触, **物体在动**) 三个概率
- `pred_obj_vel` `[B,T,3]`：物体速度
- 接触段起止（boundary）辅助头

实测接触 F1：左手 0.950、右手 0.956、物体运动 0.975。**接触检测已经不是瓶颈**。

### 2.3 ObjectTrans（`model/rnn/object_trans*.py`）
逐帧把四路候选融合成物体位置：

```
p(t) = w_L·(h_L(t) + R_obj(t)·b_L(t))     ← 左手 FK
     + w_R·(h_R(t) + R_obj(t)·b_R(t))     ← 右手 FK
     + w_I·(p(t-1) + v_obj(t)/FPS)        ← 速度积分
     + w_S· p(t-1)                        ← 静止保持
```

其中 `b_h(t)` 是**手→物体中心的骨向量，表达在物体坐标系下**，由 head 逐帧回归（v2）或
以软锁存方式产生（v3，见 §7）。融合权重 `w` 不是学出来的，而是接触概率的固定函数
（`utils/object_fusion.py`）：

```
p_L^cond = clamp(p_L / max(p_move, ε)),   p_R^cond = clamp(p_R / max(p_move, ε))
no_hand  = (1 - p_L^cond)(1 - p_R^cond)
scores   = [ p_L , p_R , p_move · no_hand , 1 - p_move ]
w        = scores / Σ scores
```

含义：**手在碰就信 FK；物体在动但没手碰就信 IMU 积分；物体不动就保持不动。**

推理协议：在线滑窗，`online_window=60`、`online_lookahead=10`，即每帧只用过去 60 帧 + 未来 10 帧，
逐帧发布（`model/rnn/imuhoi_model.py::_inference_online_sequence`）。这一点很重要——
任何跨越窗口的状态（比如接触段锁存）都必须显式回传，否则每滑一帧就被重置一次。

## 3. 核心：接触刚性固连的 FK 假设

### 3.1 数学形式

设 `t₀` 为一次抓握的起始帧，`h(t)` 为手上锚点的世界坐标，`R_obj(t)` 为物体朝向，
`p(t)` 为物体中心。定义**骨向量**（bone / virtual bone）为物体系下的手到物心向量：

```
c(t) = R_obj(t)ᵀ · ( p(t) − h(t) )                                    ……(1)
```

**刚性固连假设**：一次抓握内手与物体之间无相对运动，于是 `c(t)` 恒定：

```
c(t) ≡ c(t₀) = d₀ · L₀ ,     d₀ 为单位方向，L₀ 为长度               ……(2)
```

于是物体位置由前向运动学给出：

```
p̂(t) = h(t) + R_obj(t) · d₀ · L₀                                     ……(3)
```

双手同时接触取平均，无接触时保持上一帧位置。**这就是 `obj_trans_err` 的全部来源结构。**

实测：骨向量平均长度 **35.4 cm**，一次接触段内手相对物体平均转动 **43.9°**。

### 3.2 假设为什么会破，以及破的量

式 (2) 不严格成立，误差有三个来源，按贡献从大到小：

**(a) 锚点不是真正的接触点 → 手一转，锚点绕真接触点画弧。**
这是最大的一项。设真实接触点相对锚点的偏移为 `v`（在手坐标系下），手相对物体的旋转为

```
R_rel(t) = R_obj(t)ᵀ · R_hand(t) ,     M(t) = R_rel(t) · R_rel(t₀)ᵀ    ……(4)
```

则骨向量的漂移有**解析形式**：

```
c(t) = c(t₀) − ( M(t) − I ) · v                                       ……(5)
```

几何直观：锚点绕真接触点转 θ 角，弧长 ≈ `2|v|·sin(θ/2)`。实测这个预测弧长 5.75 cm
对实测漂移 6.41 cm，相关系数 r = 0.53。按转角分箱看得更清楚：

| 手相对物体转角 | 0-10° | 10-20° | 20-30° | 30-45° | 45-60° | 60-90° | >90° |
|---|---|---|---|---|---|---|---|
| 锚点漂移 (cm) | 1.08 | 2.25 | 3.54 | 4.92 | 7.11 | 11.55 | 19.38 |
| 帧数 | 32849 | 43920 | 34082 | 34421 | 20664 | 22403 | 29017 |

**(b) 握点滑移（grip slip）**：手在物体上缓慢挪动。
用最优 `(anchor, v)` 拟合后剩余的残差里，**92% 是慢漂移而非抖动**；
接触几何的迁移速率 p90 = 0.80 mm/帧、p99 = 2.81 mm/帧，一段内净迁移 p90 = 6.9 cm。
所以 (a) 和 (b) 在时间尺度上可分：(a) 跟着转角瞬时变化，(b) 是秒级的缓慢项。

**(c) 首帧锚定的运气**：`c(t₀)` 只是段内众多可能值中的一个。
首帧骨向量相对段内均值的偏差平均 5.69 cm（中位 2.45）——
**光是把锚点从"首帧值"换成"段内最优常量"，误差就从 6.41 降到 3.45。**

### 3.3 ⚠️ 一个必须知道的代数退化

任何试图"从物体旋转推出手的旋转"的方案都会**退化成手腕锚定**。
若令 `R_hand(t) := R_obj(t)·C`（C 为常量抓握变换），则 `R_rel(t) ≡ C`，`M(t) ≡ I`，式 (5) 的残差项恒为零，
FK 退回式 (3)。数值验证过三种此类配置，结果**完全相同的 9.08 cm**（= 手腕锚定的数值）。

**结论：残差项要有意义，`R_hand` 必须来自独立于物体的观测。**在 6-IMU 设定下只有**前臂/肘 IMU**。
这条约束直接决定了 v3 该用什么特征（见 §7.3）。

## 4. 接触锚点怎么选：腕关节 vs 指根 vs 掌心 vs 最优枢轴

这是本工作里一个被反复测过的问题。**[oracle]**，1837 个接触段、217,356 手-帧，帧加权：

| 锚点 | 定义 | L0 首帧冻结 | L1 段内最优常量 |
|---|---|---|---|
| **手腕** | SMPL 关节 20/21 | **9.08** | 4.98 |
| **掌根（当前使用）** | SMPL-24 槽位 22/23 = SMPL-X `middle1`（中指掌指关节 MCP） | **6.41** | 3.45 |
| **掌根 + 腕关节锁死** | 掌根偏移在段首冻结到肘系（模拟腕部不可观测） | **7.65** | 4.29 |
| 逐帧真值重锚 | 上界参照 | 0 | 0 |

**读法**：
1. **锚点从手腕挪到掌根，误差降 2.67 cm（29%）**。原因很直接：手腕离真实握点远，
   手一转杠杆更长。这是本项目里"免费"收益最大的单个选择。
2. 掌根具体定义（`utils/human_pose.py`）：SMPL-H 用关节 25/40、SMPL-X 用 28/43，都是**中指 MCP**。
   选它是因为它在腕部中轴线上（静息位 z 偏移仅约 2 mm），是最接近掌心的原生关节；
   而食指 MCP 偏向拇指侧 2.2 cm。对 22 关节输入则用肘-腕连线外推
   （`PALM_EXTENSION_RATIOS = (0.43, 0.42)`）构造虚拟掌根。腕到掌根实测 11.56 cm。
3. **腕关节锁死的代价是 +1.24 cm**（6.41 → 7.65）。这是 6-IMU 系统的**真实处境**：
   段内手腕平均转动 14.06°、1.51°/帧，这部分运动系统看不见。
   HPE 输出的掌根位置本质上是"肘的朝向 + 学到的腕角先验"推出来的。

**最优刚性附着点在哪？** 对每个接触段做最小二乘 `min_{v,q} Σ‖a(t) + B(t)v − q‖²`
（`B = R_objᵀR_hand`），可辨识的段占 78%（1σ < 1 cm）：

- 相对掌根的偏移 `|v|`：**中位 4.92 cm**，IQR [3.58, 6.31]
- 相对手腕：中位 10.61 cm（掌根在 11.56 cm 处，即最优点比掌根**略靠近手腕约 2 cm**）
- 解剖坐标（原点在腕）：纵向（远端）约 9.5 cm、桡侧约 −1 cm、法向（掌心侧）约 ±2 cm（左右手符号相反）
- **44.8% 的最优枢轴落在手部凸包内部**，64.9% 在 1 cm 内，78.4% 在 2 cm 内，94.3% 在 5 cm 内

**这说明它是一个真实的物理握点，不是数学抽象。**但它**必须逐次抓握推断**：
全局共享一个 `v` 收益为零（6.41 → 6.40，全局最优 `|v|` 只有 0.55 cm，等于放弃了这一项）；而每段最优 `v` 的中位 4.82 cm、IQR [3.2, 9.2]，个体差异远大于共享值。

## 5. 假设的天花板：完整阶梯

### 5.1 假设层面 [oracle]（`scripts/fk_ceiling_ladder.py`，可复现）

单手、段内、帧加权，全部用掌根锚点：

| 层级 | 含义 | 误差 | 参数量 | 可观测？ |
|---|---|---|---|---|
| **L0** | 首帧冻结骨向量 —— **v1/v2 的 FK 分支就在这一层** | **6.41** | 0 | ✅ |
| **L1** | 段内最优常量骨向量（只挪锚点，无残差） | **3.45** | 3 | ❌ 需真值 |
| **L2** | 首帧锚点 + 每段最优枢轴残差（肘系） | 3.60 | 3 | ⚠️ 枢轴需在线推断 |
| **L3** | 最优 (锚点, 枢轴)，**肘系** | **2.27** | 6 | ⚠️ 同上，旋转源可观测 |
| **L4** | 最优 (锚点, 枢轴)，**腕系** | **2.13** | 6 | ❌ 腕部旋转不可观测 |
| **L5** | L3 每 30 帧重估一次 | **0.76** | 6/30帧 | ⚠️ |
| **L6** | 逐帧重锚 | 0 | — | ❌ |

**四个关键读数：**

1. **L0 → L1 = 2.96 cm**：光是"锚点选得更好"就占了将近一半误差。而且这不需要任何新观测量，
   只需要模型能在段内推断出一个更好的常量——这正是 v2 逐帧回归在做的事，也是它比硬锁存强的原因。
2. **L3 (2.27, 肘系) ≈ L4 (2.13, 腕系)**：**用可观测的前臂旋转代替不可观测的腕部旋转，只损失 0.14 cm。**
   这是 v3 结构化残差可行性的直接依据（另有 Spearman 相关：前臂 0.68 vs 不可观测的手-物夹角 0.75）。
3. **L3 → L5 = 1.51 cm**：残差的大部分是慢漂移（握点滑移），周期性重估能吃掉。
4. **L4 = 2.13 是这一族方法的硬地板**：即使给你完美的手、完美的接触、完美的腕部旋转，
   只要坚持"一次抓握内几何刚性"，段内就还有 2.13 cm。要突破必须放弃刚性假设本身。

**按物体看 L0**（越大越难）：whitechair 10.11、clothesstand 9.83、tripod 9.56、woodchair 8.52 ｜
largetable 2.36、smalltable 3.37、floorlamp 4.55。
**规律：被转动/换手/调整握法的物体难，被整体平移的物体简单。**这个规律在真实 pipeline 上同样成立。

### 5.2 序列级 [oracle]

把 §5.1 的 L0 放进完整的"双手平均 + 无接触静止保持"流程，在评测集上算标准指标：

| | obj_err | hoi_err |
|---|---|---|
| **oracle FK（真值手、真值接触、每段真值锚定）** | **5.03** | **5.01** |
| 全集 1173 文件版本（含 87 条无接触标签序列） | 9.49 | 5.05 |

**5.03 就是"物体分支做到极致"的目标值**，请拿它和 pipeline 的 13.92 对比，不要用 9.49。

## 6. 真实误差去哪了：预测输入下的分解

用完整 pipeline 的输出做逐帧 dump，然后逐级把真值替换成预测值
（`scripts/dump_ot_predictions.py` + `scripts/analyze_ot_dumps.py`）。评测集 1015 条，在线协议：

| 估计器 | obj_err | hoi_err | 增量 |
|---|---|---|---|
| O0 真值手 + 真值接触 + 每段真值锚定 | **5.03** | 5.01 | 基准 |
| O4 同上但锚点用自身上一帧递推 | 5.48 | 5.51 | +0.45（锚点继承） |
| O5 真值手 + **预测接触** + 递推 | 7.95 | 8.05 | +2.5（接触误差） |
| **O1 预测手 + 真值接触 + 真值锚定** | **13.02** | 11.94 | **+7.99（手！）** |
| O1r 预测手但扣掉根节点漂移 | 10.89 | | 根漂移单独值 ≈ 2.1 |
| O1l 真值手只加根节点漂移 | 9.32 | | |
| O2 预测手 + 预测接触 + 真值锚定 | 13.63 | 13.13 | +0.6 |
| O3 预测手 + 预测接触 + 递推 | 15.31 | 14.43 | +1.7 |
| **v2 实际模型** | **14.51** | 10.05 | 学到的 head 比 O3 好 0.8 |
| **新 v3 实际模型** | **13.92** | 9.46 | |

**结论极其明确：手部误差 8 cm，接触误差 2.5 cm，锚点继承 0.5 cm，假设本身 5 cm。**

手部误差的构成（接触段内，相对段首的漂移）：

| onset 后帧数 | 物体误差增量 | 掌根漂移 | 其中根节点 | 其中臂链局部 |
|---|---|---|---|---|
| 1-15 | 4.2 | 3.8 | 1.7 | 3.4 |
| 16-30 | 6.1 | 8.2 | 3.6 | 7.1 |

  真值静止帧占 26%（在线评测集；离线全序列口径 29.5%）。
- **在线协议代价**：offline 整段推理 → online 滑窗，obj_err +0.43、jitter +4.0；

## 7. ObjectTrans 架构演进：v2 → v3a（失败）→ v3b（成功）

### 7.1 v2（基线，`object_trans_v2.py`）
head 每帧独立回归 `(方向 3, 长度 1) × 2 手`，融合权重固定为接触概率的函数。
优点是逐帧可自我纠正，缺点是"段内刚性"这个先验完全靠数据学。

### 7.2 v3a：硬锁存 + 结构化残差 —— **失败，已废弃**

设计（严格按 §3.2 的式 (5)）：接触 onset 时一次性提议 `(anchor, pivot)`，段内冻结，
骨向量由 `c(t) = anchor − (M(t) − I)·pivot` 解析给出，`M` 用可观测的 `R_objᵀR_forearm` 构造。

结果 **全面劣于 v2**：obj_err 15.05 vs 14.69，hoi 12.51 vs 11.34，jitter 13.18 vs 10.82。
offline 整段推理下同样输（14.89 vs 14.08），**所以不是在线滑窗截断造成的**
（我实现了跨窗口锁存状态回传，jitter 从 13.18 回落到 10.83，但均值纹丝不动）。

**三条失败机制（都有序列级证据，务必避免重蹈）：**

1. **一次性提议放弃了自我纠正**。onset 帧骨向量误差 10.01 vs v2 的 8.80——
   head 在 onset 看到的是同一份含误差的手，却失去了逐帧修正的机会，一个错误锁 100 帧。
   重放实验佐证：把 v2 的骨向量换成"首帧继承 + 半径 r 内的模型修正"，任何 r 都比 v2 差
   （r=3/5/10/15 → 15.52/15.13/14.85/14.81 vs 14.08）。
2. **pivot 在大相对旋转下失控**。pivot 上限 25 cm，段内 `|(M−I)·pivot|` p99 达 15.3 cm；
   残差 >10 cm 的段平均误差 24.1 vs 15.3。更根本的是 **pivot 在 onset 帧不可辨识**
   （M = I 时对输出无影响、无梯度），只能靠先验猜。
3. **再抓握时不重锚**。同一段接触内换手/调整握法时，接触概率从不掉到 off 阈值以下，
   旧 anchor 被一路带过去。椅子类物体因此崩溃（whitechair +3.5、woodchair +2.6）。

### 7.3 v3b：软锁存 + 可观测几何 + 静止硬门控 —— **成功，当前版本**

三处改动：

**(1) 学习的软锁存**（`model/rnn/object_trans_v3.py`）。
head 每帧输出 `(方向 3, 长度 1, 门控 logit 1) × 2 手`，有效骨向量是逐帧提议的 EMA：

```
α(t) = gate_floor + (1 − gate_floor)·σ(logit)        α ∈ [gate_floor, 1]
b(t) = b(t−1) + α(t)·( proposal(t) − b(t−1) )
接触 onset 处强制 α = 1（重置到当前提议）
```

`α ≡ 1` 精确退化成 v2 的逐帧回归，`α → 0` 是段内硬锁存，**由 head 逐帧自己决定**。
这保留了 v2 的自我纠正能力，同时表达"段内刚性"这个先验。

**(2) 可观测的抓握几何**。把 `R_objᵀ·R_forearm`（两手共 12 维 6D）拼进 head 输入，
并额外注入"相对当前接触段起点的 swing" `R_rel(t)·R_rel(t₀)ᵀ`。
依据是 §5.1 的 L3 ≈ L4：前臂旋转是腕部旋转的合格替代品。
注意 §3.3 的退化：这个特征**必须**来自前臂 IMU，不能从物体旋转推。

**(3) 物体静止硬门控**（写在基类 `object_trans.py`，v2/v3 共用，`object_trans_static_gate`）。
物体 IMU 因果规则（近 5 帧旋转 < 0.6° 且 |acc| < 0.35）或 VC 的 `p_move < 0.5` 判定静止时，
融合权重强制为 `[0,0,0,1]`（保持上一帧）。规则检测器精度 0.995、召回 0.66。

**(4) 在线滑窗回传锁存状态**（`SEGMENT_STATE_OUTPUT_KEYS`）。
`imuhoi_model.py` 把已发布的 `(bone, segment_rel_rot6d, contact_active)` 作为 known prefix 传回 OT，
否则每滑一帧锁存被重置。单独看它只影响 jitter（13.18 → 10.83），不影响均值，但任何带段状态的设计都必须做。

## 10. 往哪里努力（按证据强度排序）

### ★★★ 方向 1：把物体 IMU 当作人体的第 7 个传感器（最大空间，~8 cm）

**依据**：O1 vs O0 = 13.02 vs 5.03，手部误差占 8 cm，是其他所有项之和的两倍以上。
物体侧已经接近榨干（新 v3 的 13.92 距 O1 的 13.02 只剩 0.9）。

**为什么可行**：接触期间刚性抓握意味着 `R_hand(t) = R_obj(t)·C`，C 在段内为常量。
也就是说，**接触期间手的朝向变成可观测的**（平时只有前臂 IMU），物体的加速度也就是手的加速度。
当前 pipeline 完全没有利用这一点——物体 IMU 只进了 VC 和 OT，从未回流到 HP。

**具体做法**：训练一个接触条件化的姿态精化模块，输入 `(R_obj, a_obj, 接触概率, HP 输出)`，
输出手臂链（肩-肘-腕）的修正量。或者直接把物体 IMU 作为第 7 路输入喂给 HP，用接触概率做门控。

**天花板**：消掉臂链局部漂移 → 9.32（O1l）；全消 → 5.03（O0）。
段内掌根漂移 = 根节点 6.45 + 臂链局部 11.06（RMS 合成 13.26），两者都有份。

**注意**：直接把人体整体拉向物体（landmark 式）已证伪（§9），因为误差主要在臂链而非根节点。
要做的是**约束手臂的相对姿态**，不是平移整个人。

### ★★★ 方向 2：双手刚性约束（54% 的接触帧为双手）

**依据**：54% 的接触帧双手同时接触。双手同时抓一个刚体时，
`R_objᵀ(h_L − h_R)` 在段内应为常量——这是一个**不依赖任何真值的自洽约束**。

对 obj_err 本身可能不直接（双手平均已经抵消了部分差分误差），但它是一个强的人体姿态约束，
可以喂回方向 1 的精化模块，也可以做成训练损失。**尚未实现，未测过。**

### ★★ 方向 3：把静止门控从规则升级为学习

**依据**：门控已验证 −0.27。当前用的是手工规则（精度 0.995、召回 0.66），
而 VC 的物体运动 F1 已达 0.975，说明学出来的检测器空间还有。
真值静止帧做理想否决可再降 0.6（13.92 → 13.32）。

**做法**：把静止判定并入 VC，或在 OT 里加一个显式的静止头 + 静止一致性损失
（静止帧上惩罚 `‖p(t) − p(t−1)‖`）。上限 −0.6，成本低。

### ★★ 方向 4：段内重锚 / 再抓握检测

**依据**：L1（段内最优常量锚点）3.45 vs L0 6.41，L5（每 30 帧重估）0.76 vs L3 2.27。
当前 v3b 的软锁存已经部分做到（α 随段内推移收紧），但**"同一段接触内的再抓握"仍然做不好**
（序列 444 两段接触、中途换手，整段 obj_err：v2 11.99、v3a 11.35、v3b 13.68——v3b 在这类序列上反而更差）。

**做法**：显式的再抓握检测触发重锚。可用信号：前臂-物体相对旋转的突变、
双手接触概率的交换、骨向量提议与有效骨向量的持续偏离（当前均值 1.9 cm、p90 3.9 cm，可作阈值）。
用"物体开始运动"而非"接触开始"作为锚定时刻也值得试
（oracle：O1m 11.69 vs O1 13.02；但作为硬约束会抬高尾部，见 §9 的教训——**当作软先验，别当硬约束**）。

### ★ 方向 5：训练协议与在线协议对齐

**依据**：训练窗口 60 帧、窗口起点用真值 `obj_trans_init`，而测试时 **52.7% 的接触帧在 onset 60 帧之后**。
段内误差从 1-15 帧的 4.2 涨到 121+ 帧的 12.6，正是训练完全没覆盖的区间。
这也是"v3a refine 变体训练损失低 15% 但在线评测更差"的根源。

**做法**：长窗口 / 跨窗口 stateful 训练（TBPTT）、或直接用在线协议做微调。
注意：**简单给初值加噪声已证伪**（§9），要做就做真正的长视野。

### ★ 方向 6：模型集成 / 分歧门控

**依据**：v2 与 v3 的失败序列**互补**——逐序列取优可到 12.74（两者分别 14.51 / 13.92），
两条轨迹直接平均 13.74。最便宜的落地是双 head 平均（约 −0.3），
更有意思的是把两者的分歧当作置信度信号去驱动融合权重。

### 不建议再碰
物体加速度的任何积分/滤波方案（§9 前三行）。合成 IMU 的加速度由位置的平滑二阶差分生成，
与位置轨迹在数值上不自洽，任何依赖 `∫∫a` 的方法都会被这个不自洽吃掉。
**如果换成真实 IMU 数据（noitom/），这个结论需要重新验证。**

### ⚠️ 方法论提醒（踩过的坑）
1. **不要引用归档的评测数字**。同一 checkpoint 跨版本重评可以漂移很大
   （本项目实测 hoi_err 16.55 → 11.34，root 10.16 → 6.57，因为评测代码和测试集清单变了）。
   **每次对比都要在同一份代码、同一份数据上重跑基线。**
2. **训练损失 ≠ 评测指标**。v3a 的 refine 变体训练测试损失低 15%，在线评测反而更差。
   窗口化损失和自回归滑窗推理之间隔着一层。
3. **筛选样本时小心选择偏差**。曾经按残差相关的量（σ_o）筛段，导致阶梯虚低；
   应按纯几何的可辨识性筛。
4. **oracle 数字要说清楚在哪个集合上算的**（1173 文件 vs 1015 评测序列，差 4.5 cm）。
