## 4. 背景 B：锁腕（不可观测腕旋转）的代价

### 3. 刚性手腕：FK 假设退化 18%，且靠先验补不回来

先确认前提成立：`_SENSOR_ROT_INDICES = [0,4,5,15,18,19]`——**IMU 旋转取的是肘关节（18/19），不是腕（20/21）**。输入端确实完全观测不到腕部旋转，所以这是真实情况而非悲观假设。

实现：把腕的局部旋转锁为单位阵，即 `p_palm = p_wrist + R_elbow(t)·o_rest`，掌根刚性跟随前臂。掌根在腕系下的偏移标准差实测为 0.0 mm，运动学精确。

| 指标 (cm) | 可动腕 | **刚性腕** | Δ | 最优常量腕姿 |
|---|---|---|---|---|
| 掌根位置本身的偏移（接触帧） | 0 | **4.22** | — | 3.43 |
| **obj_err** 全部 1176 条 | 9.61 | **10.44** | +9% | 10.58 |
| **obj_err** 有接触 1086 条 | 5.86 | **6.75** | +15% | — |
| **hoi_err**（pred手=估计掌，同真实 eval） | 5.05 | **7.78** | **+54%** | 7.04 |
| hoi_err（pred手=真掌，只看物体轨迹退化） | 5.05 | 6.12 | +21% | 6.25 |
| 段内 FK@首帧 | 6.41 | **7.58** | +18% | 7.82 |
| 段内 frozen@段内最优 | 3.45 | 4.20 | +22% | — |
| （对照）直接用腕关节做锚点 | 9.08 | 9.08 | 0 | 腕位置与腕旋转无关 |

四点结论：

1. **FK 假设本身退化 18–22%**，明显但不致命。obj_err 只涨 9%（被无接触段的 static hold 稀释了），有接触序列上涨 15%。
2. **受伤最重的是 hoi_err（+54%）**，因为它是手相对量：其中 +21 个百分点来自物体轨迹变差，剩下的来自掌根自己就偏了 4.2 cm。
3. **即使锁腕，掌根外推（7.58）仍然明显好于直接用腕关节（9.08）**，所以 middle1 这个选择在无腕旋转的情况下依然值得保留。
4. **最优常量腕姿救不了 FK。** 我拟合了全数据集接触帧上的最优常量腕局部旋转（L 21.4°、R 16.0°）：它能修正**绝对位置**（掌偏移 4.22→3.43，hoi_err 7.78→7.04），但 **FK 误差反而略升（7.58→7.82）**。原因是 FK 误差取决于锚点在**物体系里的运动轨迹**，锁腕后锚点跟着前臂转而不是跟着手转，任何常量重定向都改不了这个运动模式。

所以这 +18% 是"不观测腕旋转"的硬代价，靠静态先验补不回来。真实系统落在 6.41 和 7.58 之间，取决于网络能多好地从上下文（前臂轨迹、接触状态、物体运动）反推腕部旋转——这反过来说明**让 HPE 显式监督腕部局部旋转是有价值的**，它直接买到 FK 分支约 15% 的上限。

## 5. 背景 C：符号约定 G / W 与腕旋转统计

### 一、符号：我上一轮把 `C` 同时当成"量"和"模型名"用了，这是混淆的来源

**两个量**（都是旋转矩阵，描述"手的朝向"在不同参考系下的表达）：

| 记号 | 定义 | 物理含义 | 刚性时 |
|---|---|---|---|
| **G**(t) = R_objᵀ(t)·R_hand(t) | 手在**物体系**下的朝向 | "手相对物体摆成什么姿势" | 抓握刚性 → G 恒定 |
| **W**(t) = R_forearmᵀ(t)·R_hand(t) | 手在**前臂系**下的朝向，即**腕关节局部旋转** | "手腕弯成什么角度" | 腕不动 → W = I |

**三个模型**（都是"怎么估出 R_hand"）：

- 物体耦合：`R̂_hand = R_obj · Ĝ` — 需要猜 G
- 前臂耦合：`R̂_hand = R_forearm · Ŵ` — 需要猜 W
- 现状（锁腕）：`R̂_hand = R_forearm` — 即假设 Ŵ = I

**"物体是更弱的先验"就是说 Ĝ 比 Ŵ 更难猜。** 数据：段内 G 绕自身均值漂 **24.5°**，W 只漂 **14.1°**。原因很物理——腕关节的解剖活动范围有限（屈伸 ±70°、尺桡偏 ±30°，旋前旋后在前臂里），所以 W 天生被约束在一个小范围；而手在物体上可以任意重新摆放握姿，G 没有任何这种约束。

---

### 二、接触段内手腕转动：量很大，但对 FK 的影响不是你想的那样

GT 实测，1837 个接触段 / 217356 帧：

| 手腕局部旋转 W | 均值 | 中位 | p90 |
|---|---|---|---|
| 段内变化量（绕段内均值） | **14.06°** | 10.46° | 24.98° |
| 段内最大偏离 | **33.92°** | 22.87° | 62.80° |
| 绝对幅度（绕静止腕姿） | 37.40° | 33.81° | — |
| 累计转动路程 | **202°** | — | 转速 45°/s |

88.9% 的段变化 >5°，53.2% >10°，17.0% >20°。**手腕在接触段内一直在动**；累计路程 202° 但净变化只有 14°，说明是高频来回摆动而非单向转动。

**对 FK 的影响——这里有个反直觉的结果：**

| 段内腕变化 | 段数 | FK(可动腕) | FK(锁腕) | **ΔFK** | 骨方向漂移 |
|---|---|---|---|---|---|
| 0–5° | 204 | 2.27 | 2.94 | **+0.67** | 4.4° |
| 5–10° | 656 | 3.94 | 4.91 | **+0.97** | 7.2° |
| 10–15° | 433 | 6.06 | 7.46 | **+1.39** | 11.0° |
| 15–20° | 232 | 9.10 | 10.68 | **+1.58** | 15.5° |
| 20–30° | 197 | 12.64 | 13.85 | **+1.21** | 22.3° |
| >30° | 115 | 9.43 | 10.75 | **+1.32** | 16.2° |

- 腕变化 vs **FK 绝对误差**：r = **+0.268**（2.27 → 12.64 cm，5 倍跨度）
- 腕变化 vs **ΔFK（锁腕的代价）**：r = **+0.084**，各分箱恒定在 +0.7~1.6 cm

**结论：腕转得多 ≠ 锁腕代价大。** 腕旋转是"手在物体上重新定向"的**指示器**（所以和 FK 绝对误差强相关），但锁腕本身只是把锚点从"跟着手转"换成"跟着前臂转"——换了个刚体，代价固定 ~1.2 cm，与腕转多少无关。这也解释了上一轮那个现象：最优常量腕姿能修掌根位置，却修不了 FK。

所以腕旋转真正的价值不在"估准它"，而在**它是一个强的 FK 误差指示器**。而且——

> **不可观测的"手-物体相对转角"预测骨漂移：r = +0.530 / rho = +0.748**
> **可观测的"前臂-物体相对转角"预测骨漂移：r = +0.539 / rho = +0.676**

**几乎一样好。** 你不需要腕旋转来判断 FK 靠不靠谱，前臂 IMU + 物体 IMU 就够了。

### 三、v4 / v2(v3) 怎么补方向漂移

我读了 `object_trans_v3.py`——骨架其实已经对了：contact onset 时 head 提一个 `anchor_proposal`（物体系向量），段内保持，每帧加一个 `tanh(·)×0.10m` 的自由残差，配 logvar 门控。问题不在结构，在于**残差是自由的、且没有能预测漂移的输入**。

新测的天花板（段内单手 FK，帧加权 cm）：

| 方案 | 误差 | 需要什么 |
|---|---|---|
| 首帧冻结锚点、无残差 | 6.41 | — |
| 仅换锚点：段内最优常量 | 3.45 | 锚点要代表整段 |
| **前臂系刚性枢轴（结构化残差）** | **2.27** | **结构全可观测**，(q,o) 每段推断 |
| 腕系刚性枢轴（对照） | 2.13 | 需要腕旋转，观测不到 |
| 前臂系但 o 全局共享 | 3.50 | ← 没用 |
| 前臂系但 o 按物体类别共享 | 3.53 | ← 也没用 |

**前臂系（2.27）几乎追平需要腕旋转的理论最优（2.13）**，而它只用 R_obj 和 R_forearm，两个都来自 IMU。

### 改进 1：把自由残差换成结构化残差（最大收益）

现在：
```python
left_vector = left_anchor + torch.tanh(res) * 0.10          # 3 维自由残差, 每帧
```
改成：
```python
# onset 时 head 输出 (q, o) 共 6 维, 段内保持
Rrel = R_obj.transpose(-1,-2) @ R_forearm                    # 全可观测
left_vector = q_seg - torch.einsum('bij,bj->bi', Rrel, o_seg)
```
物理含义：`o` 是"真实接触点相对前臂的偏移"，`q` 是"接触点在物体系的位置"。手绕接触点转动导致的骨向量变化由 `Rrel(t)` **解析给出**，不用学。天花板 6.41 → **2.27**。

关键约束：**`o` 必须每段推断**。我测了全局共享和按物体类别共享，都退化回 3.5（等于只换锚点）。所以不能用"每个物体类别一个可学 embedding"这种简化——必须是 onset 时由 RNN 根据上下文输出，并允许段内在线细化（30 帧窗口重估能到 0.81 cm）。

### 改进 2：显式喂入 `R_objᵀ·R_forearm`（成本极低）

现在 ot 的输入是 `obj_imu`（物体**全局** 6D 旋转）+ `lhand_imu`（前臂**根相对** 6D 旋转）+ root 全局旋转，分散在三个特征块里。网络要自己学会 `R_objᵀ·R_root·(R_rootᵀR_forearm)` 这个三重复合，再自己学会"相对 onset 取差"——GRU 很难隐式学到。

直接加两组特征：
- `Rrel(t)` 的 6D 表示
- `Rrel(t)·Rrel(t_onset)ᵀ` 的 6D 表示（相对接触起始的增量）

后者就是上面 rho=0.676 的那个预测子。它同时是改进 1 的必需输入和 `logvar` 头的依据——现在 v3 的 logvar 完全靠自己从原始特征猜，给了这个才有物理依据。

### 补充：纯段内锁存 vs 在线细化（2026-09-04T09:16Z，transcript 第 827 行）

确认了：`test.window: 60`，而接触段平均长 118 帧。这个数字后面有用。

### 一、代码上，区别就是一个 `where` 的 else 分支

现在这版（`model/rnn/object_trans_v3.py:390-398`）：

```python
segment_anchor = torch.where(contact_onset, anchor_proposal, step_state["segment_anchor"])
segment_pivot  = torch.where(contact_onset, pivot_proposal,  step_state["segment_pivot"])
```

`else` 分支是**原样传递**。所以整个接触段里 `(anchor, pivot, Rrel_onset)` 是三个常量，在 onset 那一帧定死。head 每帧照常跑（RNN 隐状态在更新），但它在非 onset 帧的输出被完全丢弃。

在线细化就是把 else 换成"允许小步更新"：

```python
segment_anchor = torch.where(contact_onset, anchor_proposal,
                             step_state["segment_anchor"] + torch.tanh(d_anchor) * anchor_rate)
segment_pivot  = torch.where(contact_onset, pivot_proposal,
                             step_state["segment_pivot"]  + torch.tanh(d_pivot)  * pivot_rate)
```

`rate` 取得很小（比如每帧 2 mm），使它只能缓慢漂移、不能一帧跳走。head 输出从 14 维加到 20 维。

### 二、物理上，是"抓握绝对刚性"还是"允许握点滑移"

**纯锁存**断言：手接触物体的那一刻起，接触点在手上不动、在物体上也不动。手和物体成为一个绕接触点的铰链。整段抓握只有 **6 个自由度**（anchor 3 + pivot 3），此后每一帧的骨向量由 `R_obj` 和 `R_forearm` 的相对旋转**唯一确定**，模型没有任何自由度。

**在线细化**承认：接触点会缓慢迁移——握持在滑、手指在重新调整、双手抬箱子时负载在两手之间转移。铰链的支点自己在动。

### 三、数值上，这个假设有一半的段站不住

我测过刚性拟合的残差（用**整段最优**的常量 anchor+pivot 之后还剩多少）：

- 低频漂移 **1.84 cm** vs 高频抖动 **0.55 cm** → **92% 的残差能量是慢漂移**，不是噪声
- 接触几何的净迁移量（末 1/3 减首 1/3）帧加权 **3.03 cm**；**52% 的段迁移 >1 cm，31% >2 cm，13% >5 cm**

误差阶梯（段内单手 FK，帧加权 cm）：

| 方案 | 误差 | 段内自由度 |
|---|---|---|
| 首帧冻结 d/L，无残差 | 6.41 | 0 |
| 段内最优常量锚点，无 pivot | 3.45 | 0 |
| **段内常量 anchor+pivot（现在这版的天花板）** | **2.27** | **0** |
| 每 30 帧重估 anchor+pivot（在线细化的天花板） | **0.81** | 每 30 帧 6 个 |

**在线细化值 1.46 cm，比 pivot 本身买到的 1.18 cm（3.45→2.27）还多一点。** 它不是锦上添花，是这条路上剩下的最大一块。

### 四、我没直接做的三个理由

1. **你要的是"v2 + 改进1 + 改进2"**，改进 1 我说的是"onset 锁存、段内保持"。细化是第三个改动。

2. **有真实的退化风险。** 一旦允许段内更新，模型完全可以用增量把结构化残差**旁路掉**——把 pivot 每帧改成任意值，等价于逐帧自由回归，退回 v2，我们注入的物理结构学没了。必须靠很小的 rate 上界、或对增量加 L2 惩罚来压住。这个超参需要单独调，不适合和架构改动一起上。

3. **现在这版是干净的对照组。** v2（无结构）→ v3（有结构、锁死）→ v3+细化（有结构、可滑移），三档能把"结构化参数化值多少"和"允许滑移值多少"分开量化。这是能直接写进消融表的。

### 五、一个会影响你解读结果的实现细节

上面 2.27 / 0.81 都是 **offline 整段**的天花板。**online 滑窗推理下情况不一样**：

`_inference_online_sequence` 每个窗口都重新初始化 scan state。如果接触在窗口首帧就已经是 active，就不会触发 onset，anchor 会退回到用**已发布轨迹**在窗口首帧隐含的骨向量（`l_oe0 * l_lb0`，由 `step_obj_trans_init = prefix[:, 0]` 算出），`segment_rel_rotm` 也重置到窗口首帧。

也就是说：**online 模式下锁存的有效时长被 `online_window` 截断，不是被接触段截断。** 你的配置是 60 帧，而接触段平均 118 帧——等于每 2 秒就被动重锚一次。这本身就是一种粗粒度、非学习的"细化"。

结论：**纯锁存和在线细化的差距，在 offline 评估里会明显（2.27 vs 0.81），在 online 评估里会被这个窗口重置吃掉一部分。** 所以做消融时两种模式都要跑，否则会低估细化的价值——或者反过来，如果只看 online 数就得出"细化没用"的错误结论。

---

要我把细化加上吗？我建议的最小版本是：head 14→20 维，增量走 `tanh × rate`（anchor 和 pivot 各自的 rate 做成配置项，默认 2 mm/帧），并对增量加一个可配权重的 L2 惩罚防止旁路。默认 rate=0 时行为与现在这版逐比特一致，这样一个 checkpoint 就能跑两组消融。

### 改进 3 的可执行摘要（若要落地）

两个**全可观测**的双手刚性检验量，逐帧计算，作为接触质量/门控信号：

```python
# p_L, p_R: 左右手接触点世界坐标; R_obj: 物体世界旋转; t0: 接触段起始帧
v_obj   = R_obj.transpose(-1, -2) @ (p_R - p_L)              # 双手向量在物体系下的表达
drift   = (v_obj[t] - v_obj[t0]).norm(dim=-1)                # rho = +0.553 (vs 骨方向漂移)
dist_ch = ((p_R - p_L).norm(dim=-1)[t] - (p_R - p_L).norm(dim=-1)[t0]).abs()   # rho = +0.473
```

刚性双手抓握下二者应恒定；变大 → 抓握在变形/滑移 → 降 FK 权重、抬 velocity/static 权重。
接入点二选一：VC-v4 侧作为接触质量输出，或 ot-v3 侧直接进 `contact_weight` 门控
（现状：`contact_weight` 仅由 `contact_prob` 和 `logvar` 决定，缺这条几何一致性通道）。
