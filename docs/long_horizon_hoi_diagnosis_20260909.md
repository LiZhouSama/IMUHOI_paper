# 长视野 HOI 诊断与论文级方向（2026-09-09）

基线：canonical OMOMO 上的 `cur_hoi`（OT-current + HOI 对齐损失，VC-v4，batch 200×1），
`outputs/IMUHOI++/RNN_cano/omomo_cano_ot_variants_20260909_c/cur_hoi`。
本文回答三件事：之前为什么没做"长视野/在线协议对齐训练"和"HP 臂链精化"；HOI 误差到底卡在哪；
哪些方向物理上站得住、能写进论文、且 HOI 至少不比 current 差。所有数字为 cm（jitter 为 mm/帧²）。

## 0. 为什么之前没做那两条线

- 时间预算：上一轮把 GPU 时间花在 6 个 OT 变体 + 回放探针上（其中 1 小时被 800×4 的批量配置浪费掉），
  两条线各需要新的训练协议 / 新模块，没有排上。这是取舍，不是判断它们没价值。
- 混淆变量：用户要求的是"在 VC-v4 上比 OT-v3 与 current"，改 HP 会把对比搅乱，所以当时刻意不碰 HP。
- 现在有了长序列测试集（BEHAVE 整段，中位 1424 帧），两条线的价值可以被直接度量，见 §3–§5。

## 2. 被证伪的物理路线（scripts/rigid_coupling/）

**杠杆臂可观测性**（lever_arm_probe.py）。接触期间 p = w + R c，c 为物体系常量，
两 IMU 加速度差 a_obj − a_wrist = S[R] c 是关于 c 的线性观测（S 为数据集的平滑二阶差分算子，
已验证反演误差 2e-4）。结果：

| 设定 | 群体先验 | 物理+先验（干净） | 物理+先验（评测噪声） |
|---|---|---|---|
| OMOMO，掌心锚，全部接触帧 | 33.9 | 15.9 | 18.3 |
| 同上，起点 60–120 帧 | 33.8 | 13.0 | 15.5 |
| 同上，激励最高四分位 | 30.6 | — | 12.2 |
| BEHAVE（物体轨迹抖动，残差 2.5 m/s²） | 27.9 | 28.1 | 27.6 |

物理项有信息，但段内非刚性（掌心锚偏差中位 3.7、均值 5.4；干净残差均值 0.79 m/s²）把它压到十几 cm。
叠加模型自身 9.7 cm 的 FK 提议后反而更差（最好 13.9）；把物理残差用于多假设判别
（hypothesis_probe.py，按物体+手的 k-means 抓握位点）也只到 13.2，正确假设命中率 58%。**不作为主线。**

**运动起点回环**（loop_closure_replay.py）：把"静止物体 vs FK 提议"的差归因于根漂移并平移人体，
在 OMOMO / BEHAVE 上根误差都变差（6.0→7.95，31.3→35.7）。差值主要是骨误差而非根漂移。**证伪。**

**测试期 IMU 静止否决**（同脚本 --veto）：回放 BEHAVE obj 54.9→45.4，OMOMO 14.24→14.02，HOI 不变。
官方评测（`object_trans_static_gate: imu`，仅测试期，`behave_longseq_20260909/cur_hoi_*_staticimu_eval.json`）：

| HOI | 9.44 | 9.55 | 40.77 | 39.21 |

长序列上免费拿回 10 cm 物体误差，OMOMO 的 HOI 付出 0.1；HOI 主体不动，它只是物体侧的止血。

## 4. 机制：OT 被自己漂移的物体状态带偏（曝光偏差）

BEHAVE dump 分解：接触段内误差几乎不再增长（Δ 段内 +6.5），坏在间隙（+13.6/100 帧）与再接触；
FK 骨向量在 GT 接触帧误差 37.8（角度误差 53°）；预测起点数 1881 vs GT 388（接触碎片化）；
首次接触前误差已 40.5（物体在没人碰的时候就被拉走）。

骨误差不随离原点距离变化（OMOMO 各距离桶 8.7–9.1，BEHAVE 30–35），却随序列时间增长：
OMOMO 8.5 (0–150 帧) → 10.8 → 15.9 (300–600)；BEHAVE 18.2 → 24.6 → 29.6 → 35.2 → 33.3。

相关性（GT 接触帧，t ≥ 60）：

| 骨误差与… 的相关 | OMOMO | BEHAVE |
|---|---|---|
| 反馈状态（上一帧 published 物体）误差 | 0.43 | 0.56 |
| 窗口起点初始相对向量误差（漂移物体 − 手 vs GT） | 0.43 | 0.64 |
| 手的绝对误差 | 0.08 | 0.15 |
| 按初始相对向量误差四分位的骨误差 | 7.5 / 7.8 / 9.2 / 13.5 | 18.6 / 24.9 / 32.3 / 50.6 |

在线协议每个窗口都用**自己 published 的物体**重新计算初始几何（`_compute_init_dir_len`）并作为反馈初值；
训练时这两者永远来自 GT（`object_trans_init_noise_std: 0.0`）。模型学会了无条件信任初始几何，
一旦它与手不一致，骨向量就跟着错，物体又从错的骨向量再发布——闭环放大。
这就是"在线协议对齐训练"要解决的问题，而且是可度量的。

## 5. 论文级方向（按证据强度排序）

> **9-09 晚间更新（见 §6）**：无结构初值噪声注入已被证伪；gt_prev oracle 表明反馈回路只占长视野 HOI 的约 30%。
> 5.1 的"训练协议"一项应改为：让模型能*识别*物体状态是否可信（输入静止认证时长、FK 先验与初始几何的分歧等
> 一致性信号，并在 rollout 对齐的训练里学习使用它们），而不是笼统地少信初值；5.1 的"接触锚定"（IMU 静止否决）
> 与"长序列基准"两项不变。HP 随时间劣化（~8 cm）是第二个长视野特有分量，需要 HP 侧的漂移抑制（脚接触 ZUPT 之外，
> 手在静止物体上的 ZUPT 是物体 IMU 能提供的新锚点）。

### 5.1 主线：长视野 HOI 跟踪 = 曝光偏差对齐 + 接触锚定 + 长序列基准

- **训练协议**：(a) 窗口初值注入漂移（已启动：`cur_hoi_drift15/30`，
  `outputs/IMUHOI++/RNN_cano/omomo_cano_ot_variants_20260909_d`）；
  (b) 正式版 rollout 对齐训练：用模型自身的在线历史作 `known_obj_trans_prefix` 与窗口初值
  （`_inference_online_sequence` 已有全部机制），只对窗口尾部帧回传梯度，等价于让训练分布 = 在线分布。
  预期：OMOMO 持平或略好（短片段），BEHAVE 整段大幅改善。
- **接触锚定**：物体 IMU 静止否决（精度 0.999）作为发布层硬约束；接触碎片化用 VC 的时序一致性正则压制。
- **基准**：BEHAVE 整段（以及 IMHD/HODome 的 canonical 整段）作为长视野协议，报告误差随时间曲线，
  这是现有稀疏 IMU HOI 工作都没有的评测。
- 论文表述：*Sparse-IMU HOI collapses over long horizons because the object state feeds back into the
  grasp predictor; we align training with the online protocol and anchor the object with IMU-certified rest.*

#### 5.1.1 rollout 对齐训练的实现要点（代码事实已核对）

- 训练窗口初值：`utils/utils.py:487` `obj_trans_init = obj_trans[:, 0]`（GT）；在线协议：
  `_inference_online_sequence` 用 `prefix[:, 0]`（自己 published 的历史）作初值，并把前 W−1 帧的 published
  位置作为 `known_obj_trans_prefix` 传入；`_predict_step` 用它覆盖 `fused_pos`，即反馈状态完全来自历史。
- 对齐做法：训练时对每个窗口，先用当前模型在 no-grad 下沿序列前缀（OMOMO 中位 170 帧，代价约 3 个窗口）
  跑一遍自回归，把它在窗口起点的 published 位置作为 `obj_trans_init`、把窗口前 W−k 帧的 published 轨迹作为
  `known_obj_trans_prefix`，只对最后 k 帧回传 HOI/obj 损失。这样训练分布 = 在线分布（初值漂移 + 自洽的历史）。
- 数据侧：需要整段序列进入 batch（`IMUDataset(full_sequence=True)` + eval 的 pad 工具），窗口起点在训练器内采样。
- 廉价代理（已在跑）：只给初值加高斯漂移，不给历史；若它已显著改善 BEHAVE，则正式版值得做。

### 5.2 次线：把 HOI 地板从 ~7 cm 往下压

HOI 的地板是抓握位置歧义（O0=7.14）。可行的补充：(i) 段内软跟踪的显式抓握潜变量（学习型滤波，
替代 v3 的硬 latch，硬 latch 已被 7.14 的非刚性证伪）；(ii) 训练期用 mesh 监督"接触点在表面"的
分布式先验（回放上限约 −0.3，弱）。这两项都不足以单独成文，只能作为主线的组件。

### 5.3 不建议

杠杆臂物理估计、运动起点回环、绝对坐标归一化（骨误差与位置无关）。

`outputs/IMUHOI++/RNN_cano/omomo_cano_ot_variants_20260909_d`。

### 6.1 长序列指标：代理实验被证伪

| 变体 | BEHAVE 整段 物体 | HOI | 根平移 | obj jitter | F1 L/R |
|---|---|---|---|---|---|
| cur_hoi | 55.39 | 40.77 | 31.29 | 12.56 | 0.74/0.75 |
| cur_hoi_drift15 | 76.40 | 63.25 | 31.24 | 13.70 | 0.72/0.75 |
| cur_hoi_drift30 | 62.92 | 50.69 | 31.22 | 15.17 | 0.73/0.75 |

IMHD / HODome 整段：

| 变体 | IMHD 物体 / HOI | HODome 物体 / HOI |
|---|---|---|
| cur_hoi | 65.65 / 34.97 | 53.50 / 41.28 |
| cur_hoi_drift15 | 68.31 / 35.50 | 61.87 / 36.57 |
| cur_hoi_drift30 | 70.56 / 38.57 | 51.86 / 30.79 |

三个长序列集合方向不一致：BEHAVE 明显更差、IMHD 略差、HODome 的 HOI 反而降 5–10。说明"物体状态错了怎么办"
在不同数据集上的最优策略不同（BEHAVE 接触假阳性多，信任静止物体是保护；HODome 更像是初值真的错了）；
无结构的高斯注入让模型一刀切地少信初值，赢一处输两处，且 OMOMO 也付代价。OMOMO 在线 dump 的诊断（GT 接触帧，t ≥ 60）：

| | cur_hoi | drift15 | drift30 |
|---|---|---|---|
| 骨误差 | 9.51 | 10.32 | 10.86 |
| corr(骨误差, 反馈状态误差) | 0.43 | 0.51 | 0.57 |
| 骨误差按帧号 [60,150)/[150,300)/[300,600) | 9.1 / 10.8 / 15.9 | 9.9 / 11.3 / 23.6 | 10.4 / 11.8 / 24.4 |
| 门控均值 FK / IMU / 静止 | 0.85/0.11/0.04 | 0.85/0.10/0.05 | 0.86/0.09/0.05 |

模型并没有因此"不信任初值"，反而对反馈状态更依赖、随时间增长更快。解释：初值噪声同时进入初始几何和反馈初态，
模型无法分辨"初值对/错"，只能学到"物体位置整体有未知偏移"，骨向量吸收了这部分方差。
**结论：§4 的相关性反映的是闭环（骨向量 → 发布物体 → 下一窗口初值），不能推出"改初值分布就能修好"；
无结构的初值噪声注入被证伪，正式的 rollout 对齐训练也不应再以此为前提立项。**
长视野下骨误差随时间增长的真正驱动仍未定位，见 §6.2。

### 6.2 逐条排除随时间累积的输入回路

- **在线 l_b 统计回路**：推理时 `_compute_online_lb_stats` 用模型自身历史（最多 2048 帧）上的
  ||published 物体 − 手|| 分位数作先验，训练用 GT 前缀模拟。测试期关闭（`object_trans_lb_stats: false`）：
  OMOMO 物体 13.72→13.71、HOI 9.44→9.45；BEHAVE 物体 55.4→57.3、HOI 40.8→41.9。**不是驱动。**
  （新增尾窗开关 `lb_stats_tail_frames`，`compute_online_lb_quantiles(tail_frames=)`，测试
  `test/test_rnn_ot_lb_stats_tail.py`；300 帧尾窗的评测在跑，预期同样无影响。）
- **逐窗口重初始化回路**：对照实验 = 离线单趟推理（整段一次前向，反馈连续、初始几何只在第 0 帧用 GT 算一次）
  vs 在线协议（每帧用自己 published 的历史重算初始几何 + 已知前缀）。`eval_IMUHOI.py --inference_mode offline/online`
  结果（`cur_hoi_*_seqeval_offline.json`）：

  | | 在线协议（batch_online） | 离线单趟 |
  |---|---|---|
  | BEHAVE 整段 物体 / HOI / MPJPE / 根 | 55.39 / 40.77 / 7.06 / 31.29 | 46.52 / 30.35 / 6.26 / 30.86 |
  | OMOMO 物体 / HOI / MPJPE | 13.72 / 9.44 / 3.00 | 13.37 / 9.28 / 2.61 |

  逐窗口重初始化解释了 BEHAVE 崩溃的约四分之一（HOI 40.8→30.4）；离线仍有 30，远高于短片段的 20，
  说明反馈状态/隐状态在长序列上的累积仍是主体（离线的 HP 也略好：MPJPE 7.06→6.26，HP 同样受在线分窗影响）。
  逐序列的在线一致性检查因太慢（预计 5.5 h）被中止。
- **反馈状态回路（教师强制）**：`scripts/diagnose_object_trans_feedback.py` 的 `gt_prev` 模式把每帧反馈状态强制为 GT
  （初始几何仍来自 published 历史），BEHAVE 全部 59 条 + OMOMO 前 240 条评测中（`feedback_diag/`）。
  结果（`feedback_diag/*.log`，该脚本关闭了 refine，故 normal 与官方数字略有差异）：

  | 反馈模式 | OMOMO（前 240 条）物体 / HOI | BEHAVE 整段 物体 / HOI |
  |---|---|---|
  | normal（模型自身状态） | 14.19 / 9.44 | 54.91 / 40.66 |
  | gt_prev（每帧反馈状态 = GT） | 8.64 / 8.76 | 10.29 / 28.34 |
  | perturb（第 80 帧 5 cm 冲击） | 14.18 / 9.42 | 55.02 / 40.79 |

  gt_prev 等价于给物体一个 oracle（静止/IMU 分支都被锚在 GT 上），物体误差自然归零附近；
  但 **HOI 只降到 28.3**：即使物体状态完美，长序列上的 HOI 仍是 OMOMO 同样 oracle 下（8.76）的 3 倍。
  它包含骨向量误差以及非 FK 帧上手的绝对误差（BEHAVE 掌心误差 36 cm）。

### 6.3 BEHAVE 长视野 HOI 的因果拆分（近似，各项有重叠）

| 分量 | 证据 | 约占 |
|---|---|---|
| 跨数据集偏移（接触 F1 0.73、未见物体） | 短片段 20.1 vs OMOMO 9.4 | ~10 |
| 物体状态反馈回路（含逐窗口重初始化） | gt_prev 40.7→28.3；离线 40.8→30.4 | ~10–12 |
| HP 输入随时间劣化（根 14→31、MPJPE 5.6→7.1、掌心 36） | gt_prev 仍 28.3 > 短片段 20.1 | ~8 |
| 抓握先验地板（非刚性 + 位置歧义） | OMOMO O0 = 7.1 | ~7 |

且都有 oracle 上界可引用（反馈回路上界 12 cm，物体误差上界 45 cm）。

## 7. 2026-09-10：状态置信（state trust）与手部 ZUPT 实验

### 7.1 物体状态置信的计算方式（已实现，`object_trans_state_trust: true`）

问题：OT 的抓握偏移预测器以两种方式依赖自己发布的物体位置 p̂：窗口起点的初始几何
`(dir, len) = (R₀ᵀ(p̂₀−h₀)/‖·‖, ‖p̂₀−h₀‖)`，以及逐帧反馈特征 `Rₜᵀ(p̂ₜ₋₁−hₜ)`。长序列上 p̂ 漂移后这两路输入把
骨向量带偏（§4、§6）。设计把"要不要信这个状态"做成一个可学习、有监督、可解释的量：

1. **无状态先验头**（`prior_head`，与主预测器同构的 RNN）：输入与主预测器逐帧特征相同（物体 IMU、旋转增量、
   VC 速度、接触概率、手位置、手 IMU、l_b 统计），但**不接反馈、不接初始几何**，其 l_b 先验缺失时回退到常数
   而不是初始几何（否则状态会经 l_b 回退泄漏进来；`test_prior_head_is_independent_of_the_object_state` 保证不变性）。
   输出每手 `(dir_k, len_k)`，给出无状态 FK 提议 `P_k^prior = h_k + R·dir_k·len_k`。
   监督：`prior_hoi_l/r` = ‖(P_k^prior − h_k) − (p_gt − palm_gt)‖ 在 GT 接触帧上的均值（与官方 HOI 同构）。
2. **一致性特征** zₜ（15 维，均因果可算）：
   - 创新量 `Rₜᵀ(P_k^prior − p̂ₜ₋₁)`（k = L/R，各 3 维）及其模长（2 维）：先验认为物体该在哪 vs 状态说它在哪；
   - 双手分歧 `Rₜᵀ(P_L^prior − P_R^prior)`（3 维）及模长（1 维）：双手抓握时两只手的提议应一致；
   - 间隙年龄：自上次任一手接触概率 > 0.5 以来的帧数 / 60；静止年龄：物体 IMU 连续判静止的帧数 / 60
     （IMU 静止规则：5 帧内旋转 < 0.6° 且 |a|max < 0.35，精度 0.995）；静止标志（1 维）。
3. **置信头**：`cₜ = σ(MLP(LayerNorm(zₜ)))`，监督目标 `yₜ = 𝟙[‖p̂ₜ₋₁ − p_gt,t−1‖ < 0.10 m]`（t=0 用窗口初值），
   BCE 损失 `state_conf`。训练时对 50% 的窗口给初值加 N(0, 0.2 m) 的偏移（同时进入初始几何与反馈初态），
   这样置信头有负样本，而且偏移在 zₜ 中是**可观测**的（创新量变大）——这是与 9-09 证伪的 drift15/30 的本质区别：
   那两次噪声不可观测，模型只能学到"整体少信"。
4. **门控注入**：主预测器的逐帧输入 = 原特征 + cₜ·feedback_embed(反馈特征) + consistency_embed(zₜ)；
   窗口初始几何 = c₀·(来自状态的 dir/len) + (1−c₀)·(先验头第 0 帧的 dir/len)。
   置信低时模型退回到无状态先验，置信高时照常使用状态；门控（四路融合权重）同样看得到 zₜ 与 cₜ。
5. 推理协议不变（在线逐窗口、已知前缀），置信在每帧从当前状态即时计算；输出新增
   `state_confidence`、`prior_*_obj_trans` 等，可用于诊断。

代码：`model/rnn/object_trans.py`（`_prepare_state_trust`、`_consistency_features_at`、`_imu_rest_flags`）、
`train/rnn/loss/object_trans_loss.py`（`prior_hoi_l/r`、`state_conf`），测试 `test/test_rnn_ot_state_trust.py`。

#### 7.2.11 状态置信实验的最终结论

1. **可行的论文方法**："无状态先验 + 一致性特征 + 可观测状态污染训练"是一个可复现的长视野增益来源，
   增益随污染强度单调上升、OMOMO 代价随之上升；测试期 IMU 静止门控可叠加（BEHAVE 物体再降 8–9）。
   操作点建议：`trust_mild`（OMOMO HOI +0.6~0.8、物体持平或更好、jitter −1.7；BEHAVE final −2.7）或
   `trust`（+1.2 / −3）；`perturb`（+2.1，物体 +5 / −7）适合作为"长视野优先"的对照点。
2. **可解释的置信量**在当前先验精度下不可得（原理性），论文里应作为分析而不是卖点：一致性检验的分辨率受限于
   无状态先验的误差（OMOMO 20 cm、BEHAVE 28 cm）。
3. **评测协议**：长序列指标必须用 final checkpoint（或多 checkpoint/多种子均值），OMOMO 窗口选择的 best 在长序列上
   噪声 ±6 cm 以上；这本身是论文该报告的现象。
4. **手部 ZUPT**：负结果，可用帧 <1.5%。
5. 未做但值得做：多种子（每个变体 ≥3 个 seed）以确认 2–3 cm 的差异；用 OMOMO 在线协议全片段指标做 checkpoint 选择。

## 8. BEHAVE 全流程训练对比（2026-09-11，`behave_full_trust_20260911`）

此前所有 trust 实验都在 OMOMO 上训练、在 BEHAVE 上测试，长视野结果里混着跨数据集偏移。这一轮把同一组变体
在 BEHAVE 上**从头训练全流程**（HP → VC-v4 → ObjectTrans + joint），训练/验证用 BEHAVE 分段集
（1536 / 382 条，150–300 帧），最终指标用 BEHAVE 全长测试序列（59 条，中位 1424 帧）。这样长视野效应与
域偏移被分开：模型在同域内，只是测试序列长 5–7 倍。

### 8.1 日程换算（lr 衰减与早停）

配置里的 epoch 预算、`milestones` 与早停窗口都是在 OMOMO 上调的，那里
`batch_size × windows_per_sequence` 给出每 epoch **23** 个优化步；BEHAVE 训练集只有 1/3 大，同样设置下每
epoch 只有 **7** 步。若直接沿用，lr 会在 1/3 的优化步数后就衰减，早停也会在模型刚要改善时触发。因此编排器
（`scripts/run_behave_full_pipeline_trust.py`）计算

    scale = 每epoch步数(OMOMO) / 每epoch步数(BEHAVE) = 23 / 7 = 3.29

并把所有 epoch 量纲的键按此放大，使 lr 计划、评测间隔与早停窗口在**优化步空间里**与 OMOMO 完全一致：

| 键 | OMOMO | BEHAVE（×3.29） |
|---|---|---|
| `epochs` / `milestones` | 300 / [100, 200, 300, …] | 986 / [329, 657, 986, …] |
| `joint_train_epochs` / `joint_train_milestones` | 100 / [10…100] | 329 / [33…329] |
| `eval_interval` / `joint_train_eval_interval` | 5 / 1 | 16 / 3 |
| `vc_velocity_stage_epochs` / `vc_joint_stage_epochs` | 120 / 60 | 394 / 197 |
| 早停 patience（OT/HP/VC ‖ joint） | 40 ‖ 30 | 131 ‖ 99 |

早停的 `min_epochs` 不再手填，而是从换算后的日程推出来：**必须越过第一次 lr 衰减**，因为 MultiStepLR 衰减后
指标通常会再降一段，patience 窗口若在衰减前关闭就会砍掉正要改善的训练。
- HP / OT：`min = 首个 milestone + patience = 329 + 131 = 460`
- VC：分阶段训练（velocity → joint → endpoint 微调），窗口放在**最后一次阶段切换之后**，否则新阶段刚开始
  引入新监督时的平台期会被误判为收敛：`min = 394 + 197 + 131 = 722`
- joint 阶段：`min = patience = 99`（该阶段 lr 每 33 epoch 衰减一次）

早停机制本身也从 OT 训练器提到了 `train/rnn/train_utils.py::should_stop_early`，HP/VC 走的 `BaseTrainer`
现在同样支持（此前只有 OT 有）。

### 8.2 变体与评测

与 OMOMO 轮次相同的五个：`cur_hoi_p800`（基线）、`cur_hoi_trust_noaug`（仅模块）、`cur_hoi_trust_mild`
（初值污染 0.10 m / 25%）、`cur_hoi_trust`（0.20 m / 50%）、`cur_hoi_trust_perturb`（再加静止期状态扰动 0.20 m）。
HP 与 VC 只训练一次并由五个变体共享，因此差异只来自 ObjectTrans 与 joint 阶段。
每个变体都在 BEHAVE 全长序列上评测 **best 与 final 两个 checkpoint**（§7.2.10 的结论：长视野指标只能用 final 比）。

### 8.3 日程换算的验证（HP 阶段）

HP 的最优 checkpoint 落在第 **416** 轮，早停在第 547 轮触发（自 416 起 131 轮无改善）。第一次 lr 衰减在第
**329** 轮，也就是说**衰减之后模型还在继续改善了 87 轮**——这正是 §8.1 要防的失效模式：若沿用未换算的日程
（里程碑 100、patience 40、min 120），HP 会在第 140 轮左右停在一个仍在改善的区间。换算后的日程是必要的，
不是保险起见。

把人体、接触检测和域偏移全部修好之后，物体分支在长序列上的误差原封不动。这直接支持 §4 的机制解释
（OT 被自己漂移的物体状态带偏），并排除了"BEHAVE 差只是因为没在它上面训练"的解释。

**结论二：同域下状态污染训练的收益比跨域时大一倍以上。**

OMOMO 训练时同样两个变体在 BEHAVE 上只有 −3.5 / −7.3，同域下变成 −7.9 / −16.0：perturb 把 HOI 削掉 40%、

而 OMOMO 轮次里 trust 会让 OMOMO 自身的 HOI 贵 1–2 cm。在部署域上训练时，污染训练是净收益。

**结论三：人体侧完全不受影响**，五个变体 MPJPE 3.70–3.75、根平移 18.05–18.45、接触 F1 0.80–0.81，
说明收益确实来自物体分支。这是 OMOMO 轮次做不到的干净对照（那里 trust 会拖累 OMOMO 自身指标 1–2 cm）。

### 8.5 日程换算的事后检查（OT 阶段）

换算后的日程对 BEHAVE 的**物体分支**偏长：OT 阶段最优 checkpoint 落在第 32–112 轮，而第一次 lr 衰减在第 329 轮、
早停下限在第 460 轮；joint 阶段最优在第 24–63 轮，第一次衰减在第 33 轮。也就是说 **BEHAVE 上 OT 的 lr 衰减
从未帮上忙，模型在衰减之前就已过拟合**（训练集仅 1536 条）。按步数等比放大保证了与 OMOMO 的公平可比，
代价是每个变体多跑约 350 个无效 epoch（约 1.5 小时）。

这与 §8.3 的 HP 结论方向相反（HP 最优在第 416 轮，确实需要衰减之后的空间），说明**同一日程对不同阶段的适配度不同**：
下次在小数据集上应对 OT 阶段单独标定里程碑（例如按 §8.3/§8.5 观察到的最优点位置），HP/VC 保持按步数放大。
本轮不改，以免破坏已完成变体之间的可比性。

2. 双手闭环有真实的不一致可修（10 cm 级分歧），且共模参数化把先验的歧义从 24.5 压到 15.0；但必须保留模型的
