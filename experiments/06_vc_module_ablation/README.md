# 06 VC 模块消融（重训重测）：HP 先验、条件接触概率、身体部位

日期：2026-10-30 至 11-02。对应创新点 1（HP 姿态先验，含 v5ar 的其它新增部分）和创新点 2（条件接触概率）。OMOMO、BEHAVE 的 7 行全部完成；IMHD、PAHOI、HODome 的关键行（整包、条件概率）已完成，身体部位行还在跑。

## 问题

- 去掉 HP 先验后，接触估计和下游物体/HOI 误差会差多少？按 2026-10-31 的定义，这里的“HP 先验”连同 v5ar 中除条件接触概率以外的全部新增部分一起去掉。
- 把条件接触概率 p_s = p_m·p_{s|m} 换成 IMU-HOI 那样直接估计 p_s，会怎样？这也检验了 03 提出的机制：物体一停，手接触随之释放。
- 姿态先验里，哪个身体部位不可缺少？对应 A2（04）的剔除，但这里每一行都重新训练。

**训练与评测**
- 每个消融行都从头重训：
  1. VC 用 v5ar 配方：同一份配置、seed 42，OMOMO 300 轮 / BEHAVE 986 轮，先训速度再训接触，HP 冻结；
  2. 再用与发表版相同的编排器命令重训 OT 和联合阶段；
  3. 最后按统一协议 7/3 在线评测：best 联合检查点，seed 42 的 Noitom 测试噪声。
- 行与行之间只有 `vc_ablation_*` 键不同（`model/rnn/velocity_contact_v5.py`），整包行另把 `v5_init_noise_prob` 设为 0。
- **Full 行就是发表版。** 训练是完全确定的：用当前代码按原配置重跑 OMOMO，VC、OT 和联合检查点与发表版逐位相同（最大差 0.0），评测数值也完全一致。因此其余四个数据集的 Full 行直接用发表版，只补跑一次逐帧概率导出（与发表版评测逐项一致）。
- **IMHD / PAHOI / HODome**：它们的发表版是由编排器从 `recipe.yaml` 一次训练出 HP、VC、OT 和联合阶段的（`scripts/run_remaining_datasets_comparison.py`，调度按每轮步数自动缩放）。消融行沿用同一条编排器命令训练 VC、OT 和联合阶段，HP 复用发表版（HP 冻结，各行相同）。生成的 VC 配置与发表版逐行一致，只多了消融键。

**指标**（只统计在线发布的帧）
- 帧级 F1：手接触阈值 0.15，物体运动阈值 0.5，与流水线和主表相同；按序列取平均，只统计 GT 两类都出现的序列。与评测 JSON 逐项核对一致。
- AP：所有帧汇总后的 PR 曲线下面积，与阈值无关。直接估计的概率本来就和条件版校准不同，AP 用来排除阈值造成的差异。
- 事件 F1：用同一阈值二值化后，GT 和预测的起点/终点在 ±10 帧内一一匹配，只统计 [90, T−30) 帧（与 A1 相同）。手部为左右手合并，主表的“事件 F1”取起点和终点的平均。
- 过分割：预测接触段数除以 GT 段数，用来衡量抖动。
- 困难负样本误报：物体在动、但这只手没接触的帧里，被判为接触的比例。
- 置信区间：按序列做配对 bootstrap，1000 次，所有行共用同一组重采样。

### 1. HP 先验（整包）是接触估计和接触起止的主要来源

- **帧级**：去掉后手部 F1 在 OMOMO 降 2.9 / 2.6 个百分点，在 BEHAVE 降 4.1 / 4.4 个百分点，主要是召回下降（OMOMO 约 −3.5，BEHAVE 约 −7）。
- **起止事件**：受影响最大。手部事件 F1 在 OMOMO 从 56.2 降到 40.6，在 BEHAVE 从 29.6 降到 16.3；物体运动事件在 OMOMO 降 11.8。
- **抖动**：接触预测明显碎片化，手部过分割在 OMOMO 从 2.9 升到 5.2，在 BEHAVE 从 3.0 升到 7.3。
- **下游代价随接触难度放大**：物体 / HOI 误差在 OMOMO 增加 0.77 / 0.25 cm，在 BEHAVE 增加 2.18 / 2.04 cm，后者约为 OMOMO 的 3–8 倍。BEHAVE 的接触更难，对接触错误也更敏感，与 05（A3）一致。
- **五个数据集方向一致**：
  - 接触层面：手部 F1 在 5 个数据集上都下降，其中 4 个至少一只手显著；物体运动 F1 在 5 个数据集上都下降，3 个显著；手部事件 F1 在 4 个数据集上显著下降（PAHOI −4.6 不显著，它的事件置信区间约 ±12）。HODome 下降最多：左手 F1 −10.5，手部和物体运动事件都 −18.8 左右。
  - 下游：物体误差的点估计在 5 个数据集上都变差，3 个显著（OMOMO、BEHAVE、PAHOI）；HOI 误差在 OMOMO、BEHAVE 上显著变差，在其余三个数据集上不显著。IMHD 和 HODome 的测试序列少（15、36），下游置信区间约 ±1.5–2.5 cm。

### 2. 条件接触概率：压制“物体在动但手没碰”的误报，让接触及时释放（前提是物体运动估计可靠）

OMOMO 和 BEHAVE 上方向完全一致：
- 改成直接估计后，精确率下降（OMOMO −1.8 / −1.9，BEHAVE −3.2 / −3.9），召回略升，即模型更容易判为接触。
- 困难负样本误报明显上升：OMOMO 从 35.2 到 40.2，BEHAVE 从 52.0 到 60.7。
- 手部释放事件 F1 下降：OMOMO −5.0，BEHAVE −9.3。
- 物体误差上升：OMOMO +0.22 cm，BEHAVE +1.14 cm。HOI 误差在两个数据集上都不显著。

这正是 03 提出的机制：手接触被写成 p_s = p_m·p_{s|m}，物体一停，p_m 下降，手接触就随之释放；物体被别的东西带动时，也不会误判为手在接触。OMOMO 上 AP 只降 0.1–0.2，差别主要在判定结构上，而不在排序能力；BEHAVE 上 AP 也降了（左手 −1.2*，右手 −0.9），直接估计在难数据集上的排序能力也更差。

|---|---|---|---|---|---|

- HODome 在接触层面与 OMOMO/BEHAVE 一致（精确率、释放事件变差），但下游不显著；PAHOI 各项都不显著。
- IMHD 方向相反：改成直接估计后精确率和下游误差反而更好（物体 −2.2 cm、HOI −1.6 cm，15 个序列，CI 宽）。IMHD 的物体运动 F1 只有 70.8，远低于其余四个数据集（92–98）。条件分解把物体运动估计 p_m 乘进手接触，p_m 不可靠时，它的错误会直接传给手接触。
- 结论：条件接触概率在物体运动估计可靠时有效（OMOMO、BEHAVE 上接触和下游都显著改善），在物体运动估计差的数据集上会起反作用。

### 3. 单个身体部位可以互相替代

- **下游**：两个数据集上，去掉任何一个部位，物体和 HOI 误差都没有显著变化（8 行的 CI 全部含 0）。
- **OMOMO**：
  - 去掉右臂、躯干或腿，手部 F1 和事件 F1 都没有显著变化；去掉左臂只让左手 F1 降 0.6（右手不变）。
  - 从召回看，两侧都有同侧效应：去左臂后左手召回 −0.7*，去右臂后右手召回 −0.7*（但精确率 +0.5* 抵消，F1 不变）。方向与 A2 一致。
- **BEHAVE**：
  - 去掉右臂后右手 F1 降 2.2*（精确率 −2.8*、召回 −2.9*），左手不变，是同侧效应。去掉左臂后两只手的 F1 都不显著，但右手召回降 3.0*。
  - 去掉手臂或躯干后接触更抖：手部过分割分别增加 0.94*（左臂）、0.75*（右臂）、0.70*（躯干），腿 +0.21 不显著。OMOMO 上没有这个现象。
  - 事件指标两个方向都有。例如去左臂后手部事件 −4.2*，物体运动事件却 +6.4*。59 个序列、单种子，单项不宜解读。
- **与 A2 对照**：在不重训的情况下剔除左臂，OMOMO 左手 F1 降 9.8 个百分点，物体误差 +1.6 cm；BEHAVE 左手 F1 降 8.6 个百分点，物体误差 +1.6 cm。重训后基本恢复。这说明训练好的网络确实在用各个部位（依赖），但任何单一部位都不是必需的，其余部位和 IMU 证据能补上（不是必要条件）。

### 4. 补充：整包效应主要不来自姿态先验本身

- 只去姿态先验（OMOMO）时：
  - 手部 F1 降 0.8 / 0.9（召回 −1.5 / −2.1），AP 降 0.2–0.3；
  - 事件 F1 不变差（+4.0 / +2.5，不显著），过分割反而从 2.9 降到 2.4；
  - 物体 / HOI 误差不显著。
- 在 0.5 阈值、OT 实际使用的 0.7/0.3 滞回、按正例率匹配的阈值三种二值化下复查，姿态先验都没有改善起止事件（见下方“附：二值化复查”）。
- 与整包相比（手部 F1 −2.9 / −2.6，事件 −15.7），大部分效应来自耦合特征、双向物体头和初始化扰动。论文里按 2026-10-31 的决定把它们并入 HP 先验这一创新点。如果审稿人要求拆开，需要补“只去耦合 / 只去双向头 / 只去初始化扰动”几行。

## 局限

- **单种子**：每行只有一个训练种子。确定性只保证同一配置可以复现；任何结构改动都会改变初始化和训练轨迹，效果相当于换种子。bootstrap 区间只反映测试集抽样，不包括这部分波动。所以 OMOMO 上小于约 0.5 个百分点或 0.2 cm 的差别（身体部位行、HOI 列）不宜下结论。
- **测试集小**：BEHAVE 59、HODome 36、IMHD 15 个序列，置信区间宽。例如 BEHAVE 整包行物体运动 F1 −1.0 不显著；IMHD 上条件概率行的反向结果也只建立在 15 个序列上。
- **重训与剔除不同**：身体部位行与 A2 的剔除回答的是不同问题，前者问“是否必需”，后者问“是否依赖”，不能互相替代。
- **阈值**：所有行都用流水线阈值。直接估计的概率校准不同，所以同时给出了 AP，结论不变。
- **身体部位行**保留了掌心动态和耦合特征，所以“w/o 左臂”不等于完全没有左臂信息。
- **OMOMO w/o 右臂的中断**：在联合阶段第 54 轮时，因 GPU 显存换页卡住，之后从检查点续训。被评测的 best 检查点（第 42 轮）早于中断，结果不受影响。BEHAVE w/o 条件概率的 final 评测也被同一次换页拖慢，数值不受影响。
- **HODome 两个关键行重跑过**：11-01 两条车道并发训练 OT 时出现了不确定的 GPU 运行时损坏（loss 变成 1.4e-45、CUBLAS 失败等）；同一命令单独重跑时，崩溃前的 loss 与崩溃那次逐位相同，之后正常，说明不是代码或数据问题。这两行已单车道从头重跑，表中是重跑结果（旧目录保留为 `*_gpu_corruption_20261101`）；重跑的整包 VC 与并发期间训练的 VC 逐位相同，说明损坏只影响了崩溃的 OT 阶段。此后所有任务单车道运行。
