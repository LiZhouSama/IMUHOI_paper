# 03 接触起止事件分析（A1）：事件对齐的接触响应曲线与事件级时刻误差

日期：2026-10-28。对应创新点 1（HP 姿态先验作为 VC 输入，预测交互起止）。

## 问题

在线推理时，VC 给出的接触决策（OT 实际使用的接触概率）在接触开始和结束前后表现如何：
- 能否检出真实的起止事件，假的状态切换多不多；
- 起止时刻差多少帧；
- 这些差别来自 VC 的哪一部分改动，是否随推理协议改变。

## 设置

四个模型都用 seed 42 和测试集。前三个共用我们的 OT（v2_armrot_biclose），联合阶段微调 VC+OT，HP 相同：

| 简称 | VC | 管线 | 原生协议 |
|---|---|---|---|
| `v5ar` | IMUHOI++ VC：运动条件分解 + 姿态先验与辅助头 + coupling 特征 + 初始化扰动 | `vc_v5_20260930_ot_{omomo_v5ar_unified,behave_v5ar}` | 7/3 |
| `v4` | 姿态先验 VC：运动条件分解 + 姿态先验与辅助头 | `v2_armrot_biclose_20260923_{omomo,behave}` | OMOMO 0/0，BEHAVE 7/3 |
| `imuhoivc` | IMUHOI 的 VC：无分解、无姿态先验 | `vc_ot_cross_ablation_{omomo,behave}_imuhoi_v2_armrot_biclose` | OMOMO 0/0，BEHAVE 7/3 |
| `imuhoi3b` | 原版三分支 IMUHOI 整条管线：联合阶段微调 HP+OT，VC 冻结 | `imuhoi3b_20261012_omomo_unified`、`imuhoi3b_20261008_behave` | 7/3 |

**协议**：
- 7/3：HP 平滑半宽 7，物体速度用已发布轨迹的 3 帧差分初始化。
- 0/0：两者都不用，VC 用自己上一窗口的输出初始化速度。
- 每个模型都分别在两种协议下导出。"原生"指该管线训练和选模时使用的协议。

**配对比较的含义**：
- `v4 − imuhoivc`：OT 和训练配方相同，只换 VC。效果来自运动条件分解、姿态先验、endpoint/anticipation 辅助头和分阶段训练的合力。relabel 之后没有"只含分解"的 VC-v3，所以无法把姿态先验单独拆出来。
- `v5ar − v4`：coupling 特征和初始化扰动。OMOMO 上还包含 v5ar 在 7/3 下重训的联合阶段。
- `v5ar − imuhoi3b`：完整方法相对原版基线。

**事件定义**：
- 每个 GT 手接触段或物体运动段，第一帧是起点，最后一帧是终点，与 endpoint 标签的约定一致。左右手合并统计。
- 只统计 ±30 帧邻域全部落在滑动窗口帧上的事件，即事件帧在 [90, T_pub − 30) 内；预测事件也限制在同一区间。
- 原因是前 60 帧由预热块一次性发布，能看到第 69 帧之前的输入。OMOMO 片段大多从接触开始，所以起点只有 112 个，终点 573 个；BEHAVE 起点、终点各约 320 个。

**指标**：
- 峰值对齐曲线：发布的接触概率在事件前后 ±30 帧的平均值。
- 事件级 F1：概率以 0.5 二值化，与 GT 事件在容差内一对一匹配。另报 OT 的 FK 跟踪所用的 0.7/0.3 迟滞规则。
- 匹配事件的时刻误差、平均曲线穿过 0.5 的时刻、过分割率（预测事件数 / GT 事件数）。
- 置信区间按序列 bootstrap，模型之间的比较用配对差值。

## 结果

完整的跨协议表见 `protocol_sensitivity.md`。

**事件级 F1**（容差 10 帧，阈值 0.5），手接触起点 / 手接触终点：

| 设置 | v5ar | v4 | imuhoivc | imuhoi3b |
|---|---|---|---|---|
| OMOMO 全部 7/3 | 0.357 / 0.704 | 0.289 / 0.647 | 0.155 / 0.464 | 0.193 / 0.484 |
| OMOMO 全部 0/0 | 0.342 / 0.686 | 0.280 / 0.640 | 0.298 / 0.636 | 0.324 / 0.625 |
| OMOMO 原生 | 0.357 / 0.704 | 0.280 / 0.640 | 0.298 / 0.636 | 0.193 / 0.484 |
| BEHAVE 全部 7/3（即原生） | 0.279 / 0.328 | 0.239 / 0.238 | 0.120 / 0.128 | 0.187 / 0.164 |
| BEHAVE 全部 0/0 | 0.268 / 0.331 | 0.225 / 0.240 | 0.152 / 0.163 | 0.190 / 0.167 |

### 在所有协议下都成立的结论

| 比较 | OMOMO（三种设置） | BEHAVE（两种设置） |
|---|---|---|
| v4 − imuhoivc，物体运动起点 / 终点 | +0.13 到 +0.26，均显著 | +0.20 到 +0.22，均显著 |
| v5ar − v4，手起点 / 手终点 | +0.062 到 +0.077 / +0.045 到 +0.064，均显著 | +0.04 / +0.09，均显著 |
| v5ar − imuhoivc，手终点 | +0.05 到 +0.24，均显著 | +0.17 到 +0.20，均显著 |
| v5ar − imuhoi3b，手终点 | +0.06 到 +0.22，均显著 | +0.16，均显著 |

**松手（手接触终点）更及时、更干净。** 这一点在所有设置下都成立：

| 指标 | 数据集 | 我们（v5ar / v4） | IMUHOI（imuhoivc / imuhoi3b） |
|---|---|---|---|
| 终点后 +11 到 +30 帧的平均手接触概率 | OMOMO | 0.04 | 0.11–0.20 |
| 同上 | BEHAVE | 0.19–0.23 | 0.32–0.43 |
| 平均曲线穿过 0.5 的时刻 | OMOMO | +0.2 到 +0.5 帧 | +1.5 到 +3.0 帧 |
| 同上 | BEHAVE | +2.9 到 +3.6 帧 | +5.7 到 +12.7 帧 |

匹配事件的误差：
- BEHAVE：v5ar − imuhoi3b 为 −3.2 [−4.4, −2.1] 帧（7/3）和 −3.8 [−4.9, −2.6] 帧（0/0）。
- OMOMO：v5ar − imuhoivc 为 −0.94 [−1.41, −0.48] 帧（原生）。

可能的机制：手接触被写成 p_s = p_m·p_{s|m}，物体一停，p_m 下降，手接触概率随之下降。v4 相对 imuhoivc 在物体运动终点上的稳定优势支持这一解释。但 v4 同时含有姿态先验，这只能算与数据一致的解释，不是隔离实验的结论。

**接触起点没有提前量。** 平均曲线穿过 0.5 的时刻：OMOMO 上所有模型都在 −0.7 到 +0.7 帧；BEHAVE 上我们 +1.4 到 +2.3 帧，原版 +0.8 到 +1.6 帧，IMUHOI-VC 更晚（+6.0 到 +6.5 帧）。匹配事件的时刻误差也没有稳定差别。这与实验 02 的"接触前读不出交互方式"一致。

### 依赖协议的结论

- **v4 − imuhoivc 的手部事件**：OMOMO 上 7/3 时为 +0.13 / +0.18，0/0 时为 −0.02 / +0.00，不显著。BEHAVE 上两种协议都显著，7/3 时 +0.12 / +0.11，0/0 时 +0.07 / +0.08。
- **原因**：OMOMO 上 IMUHOI 的 VC 在 7/3 下明显更抖。手起点过分割率从 4.0 升到 9.1，帧级手部 F1 也从 0.915 降到 0.905。IMUHOI-VC 是按 0/0 训练的，它的接触网络读取预测速度，而 3 帧差分初始化给速度带来了噪声。
- **BEHAVE 上方向相反**：0/0 让 IMUHOI-VC 的帧级 F1 从 0.794 降到 0.771，原因是长序列上速度初始化会随机游走。
- **v5ar − imuhoi3b 的手起点**：OMOMO 上 7/3 时 +0.164，0/0 时 +0.018，不显著。原版在 0/0 下的起点 F1 是 0.324。
- **对 01 主对比的含义**：评测协议本身几乎不改变原版在 OMOMO 上的物体误差（同一模型 7/3 为 17.84，0/0 为 17.81 cm）。但在接触事件上，7/3 对 IMUHOI 的 VC 不利。所以涉及接触事件的对比，应同时报告两种协议，或者报告各自的原生协议。

### 其他发现

- **提升主要来自精确率，不是召回率。**
  - 10 帧容差内的召回率在四个模型间接近：OMOMO 原生手起点 0.75–0.81，BEHAVE 0.61–0.67。
  - 差别在假的状态切换：BEHAVE 手终点精确率 v5ar 0.21、imuhoivc 0.07、imuhoi3b 0.10；手起点过分割率 3.3 对 9.6 对 5.6。
- **endpoint 辅助头不提供提前量。**
  - 在发布帧上，起点头的平均响应很弱，峰值 OMOMO 0.08–0.10、BEHAVE 约 0.03；终点头峰值约 0.22 和 0.08。
  - 两个头的峰值都出现在事件之后 3–19 帧。
  - 它的作用更像训练时的辅助监督，效果体现在主接触输出上。
- **按交互方式分层（BEHAVE，7/3）。**
  - 各模型在推/拖段上的召回率都低于搬起段，例如手起点我们 0.59 对 0.68，原版 0.55 对 0.74。这对应已知的"推大物体最难"。
  - 松手召回率我们在三类上都高于原版：搬起 0.78 对 0.59，推/拖 0.66 对 0.53，倾斜 0.68 对 0.47。

## 对论文的影响

可以写的：
- IMUHOI++ 的 VC 让接触结束（松手）的检出更及时、更干净，在两种协议、两个数据集上都成立。
  - 松手后误报概率更低。
  - 平均曲线穿过 0.5 的时刻早 1–10 帧。
  - 相对 IMUHOI-VC，手终点事件 F1 高 0.05–0.24。
  - 物体运动起止的事件 F1 高 0.15–0.33，其中 v4 已贡献 0.13–0.26。
- 图上建议用：
  - 峰值对齐曲线 `behave/peri_event.png`，OMOMO 用 `omomo_native/peri_event.png`；
  - 事件 F1 随容差变化的曲线 `*/event_f1.png`。

不要写的：
- "预测交互起止 / 提前预见接触"。起点没有提前量，endpoint 头也不提前。
- 把 v4 − imuhoivc 的提升单独归功于姿态先验。它同时包含运动条件分解、辅助头和分阶段训练；要拆开，需要补训一个只去掉姿态流的 VC。
- 只报 7/3 下 OMOMO 的手部事件对比。那里的优势有一大半来自 7/3 对 IMUHOI-VC 的不利影响。

## 局限

- 单 seed、单 checkpoint；只用测试集。
- OMOMO 的起点样本少（112 个）。
- BEHAVE 的事件 F1 绝对值较低：阈值 0.5 下，每个 GT 切换对应 3 个以上预测切换。迟滞规则能明显改善，例如 v5ar 手终点 F1 从 0.328 升到 0.427。
- 匹配事件的时刻误差是有条件的统计：召回低的模型只在容易匹配的事件上计时。所以要和 F1、平均曲线的穿越时刻一起看。
- 双向性混杂：v4/v5ar 的物体运动分支和 b_t 在窗口内是双向的，能利用 10 帧前瞻；IMUHOI 的接触网络是因果的。物体运动事件更准，部分可能来自这一点，而不是姿态先验本身。
